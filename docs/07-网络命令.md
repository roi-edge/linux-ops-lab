## 三、五个命令逐讲

### 3.1 `ip` —— 地址、路由、邻居

```bash
ip -br a                  # 接口地址，一行一个（breadth）
ip a                      # 完整信息（含 MAC、状态、valid_lft）
ip r                      # 路由表
ip route get 8.8.8.8      # 问内核：发往这个地址走哪条路
ip neigh                  # ARP/邻居表（IP → MAC）
ip link set eth0 up       # 启停网卡
```

**`ip route get` 是最实用的排查命令**，实测：

```bash
ip route get 8.8.8.8
# 8.8.8.8 via 192.168.9.2 dev ens33 src 192.168.9.128 uid 1001
#                       ^^^^^^^ 跨网段 → 走网关

ip route get 192.168.9.50
# 192.168.9.50 dev ens33 src 192.168.9.128 uid 1001
#                ^^^^^^^^^ 同网段 → 无 via，直连
```

**同网段不走网关，跨网段才走网关。** 这一条测试同时验证了路由表里 `192.168.9.0/24 ... scope link` 那行。

**`ip neigh` 实测：**

```
192.168.9.1   dev ens33 lladdr 00:50:56:c0:00:08 REACHABLE
192.168.9.2   dev ens33 lladdr 00:50:56:ea:e6:a7 STALE
192.168.9.254 dev ens33 lladdr 00:50:56:ef:d7:70 STALE
```

状态含义：`REACHABLE` 最近通信过、`STALE` 缓存过期但仍可用、`FAILED` 解析失败。

### 3.2 `ss` —— 端口与连接（07 的验收核心）

```bash
sudo ss -tlnp              # TCP 监听 + 进程
sudo ss -tulnp             # 加 UDP
sudo ss -tnp               # 已建立的连接
sudo ss -tnp state established
sudo ss -s                 # 汇总统计
```

| 参数 | 含义 |
|---|---|
| `-t` | TCP（`-u` = UDP） |
| `-l` | listening，只看监听 |
| `-n` | **numeric**，不解析端口名/主机名（排查必加） |
| `-p` | process，显示进程（**需要 root**） |

**本机实测输出（节选）：**

```
Netid State  Recv-Q Send-Q Local Address:Port      Peer Address:Port  Process
tcp   LISTEN 0      4096   0.0.0.0:22            0.0.0.0:*   users:(("sshd",pid=2704,fd=3),("systemd",pid=1,fd=183))
tcp   LISTEN 0      4096   127.0.0.53%lo:53       0.0.0.0:*   users:(("systemd-resolve",pid=883,fd=15))
tcp   LISTEN 0      4096   127.0.0.1:631          0.0.0.0:*   users:(("cupsd",pid=1620,fd=7))
udp   UNCONN 0      0      192.168.9.128%ens33:68 0.0.0.0:*   users:(("systemd-network",pid=860,fd=11))
udp   UNCONN 0      0      0.0.0.0:5353           0.0.0.0:*   users:(("avahi-daemon",pid=1205,fd=12))
```

**各列含义：**

| 列 | 含义 |
|---|---|
| `Netid` | `tcp` / `udp` / `raw` |
| `State` | `LISTEN` / `ESTAB` / `TIME-WAIT` / `UNCONN` |
| `Recv-Q` | 接收队列。**LISTEN 时 = 已完成握手、等待 accept 的连接数** |
| `Send-Q` | 发送队列。**LISTEN 时 = backlog 上限** |
| `Local Address:Port` | 本端。`0.0.0.0` 全部网卡 / `127.0.0.1` 仅本地 / `[::]` IPv6 |
| `Peer Address:Port` | 对端。LISTEN 时为 `0.0.0.0:*` |
| `Process` | `users:(("程序名",pid=进程号,fd=文件描述符))` |

#### 80 端口实战（验收现场）

```bash
sudo -v && sudo nohup python3 -m http.server 80 >/tmp/httpd.log 2>&1 &
sudo ss -tlnp | grep ':80 '
```

实测：

```
LISTEN 0  5  0.0.0.0:80  0.0.0.0:*  users:(("python3",pid=4749,fd=3))
```

**完整答案要包含四项：**

1. **程序名** `python3`
2. **PID** `4749`
3. **fd** `3`（0/1/2 被标准输入输出错误占）
4. **运行身份**——`lsof` 显示 `USER=root`（绑 1024 以下端口需要特权）

```bash
sudo lsof -i :80
# COMMAND PID USER FD TYPE DEVICE SIZE/OFF NODE NAME
# python3 4749 root 3u IPv4 30338   0t0  TCP *:http (LISTEN)
```

`3u` 的 `u` = **以读写方式打开**（`r` 只读 / `w` 只写 / `u` 读写）。

#### `0.0.0.0` vs `127.0.0.1`（安全配置的关键）

| 绑定地址 | 含义 | 外部可达 |
|---|---|---|
| `0.0.0.0:80` | **所有 IPv4 网卡地址**（= INADDR_ANY） | ✅ |
| `127.0.0.1:80` | 只有回环 | ❌ 连不上 |
| `192.168.9.128:80` | 只有 ens33 | ✅ 仅该网段 |
| `[::]:80` | 所有 IPv6 | ✅ |

**这是安全审计第一眼**：数据库只该给本机用 → 必须绑 `127.0.0.1`；绑成 `0.0.0.0` 就是"数据库暴露在公网"的经典事故。

#### `Send-Q = 5` 是什么

**LISTEN 状态下 `Send-Q` 不是"发了多少数据"，而是 backlog 上限**——内核允许"已完成三次握手、应用还没 accept"的连接排队长度。

| 列 | LISTEN 时 |
|---|---|
| `Recv-Q` | 当前队列里排着几个 |
| `Send-Q` | 队列最多排几个 |

- Python `http.server` 的 `request_queue_size` 默认 **5**
- sshd 设 **4096**
- 最终上限 = `min(程序 backlog, net.core.somaxconn)`

**太小会怎样**：队列满了内核直接丢弃新连接，客户端看到超时或 `Connection reset`。生产 nginx 要显式写 `listen 80 backlog=4096;`。

```bash
sysctl net.core.somaxconn     # 内核上限，本机默认 4096
```

### 3.3 `dig` —— DNS 查询

```bash
dig example.com                    # 完整输出（四段）
dig +short example.com             # 只要答案（脚本用）
dig A example.com +short           # 指定记录类型
dig @8.8.8.8 example.com +short    # 绕过 resolv.conf，指定服务器
dig -x 8.8.8.8 +short              # 反向查询（IP→域名，PTR）
dig +trace example.com             # 从根服务器逐级迭代
dig +noall +answer example.com     # 只看 ANSWER 段
```

**输出四段：**

| 段 | 内容 |
|---|---|
| `HEADER` | 状态码（`NOERROR`/`NXDOMAIN`/`SERVFAIL`）、标志位 |
| `QUESTION` | 问了什么 |
| `ANSWER` | **答案**（最关心） |
| `AUTHORITY` | 谁负责这个域（NS 记录） |
| `ADDITIONAL` | 附加记录 |

**ANSWER 行字段：**

```
example.com.   86400   IN   A   93.184.215.14
   域名        TTL   类  类型     值
```

- **TTL** 决定缓存多久、也决定"改 DNS 多久生效"
- `A`=IPv4、`AAAA`=IPv6、`CNAME`=别名、`MX`=邮件、`NS`=权威、`PTR`=反解

**`resolvectl` 配合查看：**

```bash
resolvectl status                  # 真实上游 DNS（resolv.conf 里看不到）
resolvectl query example.com       # 走 resolved 查询，含缓存信息
sudo resolvectl flush-caches       # 清缓存（抓包前必做）
sudo resolvectl statistics         # 缓存命中统计
```

**实测：`resolv.conf` 写 `127.0.0.53`，但 `resolvectl status` 显示真实 DNS 是 `192.168.9.2`。**

```
resolv.conf mode: stub
Current DNS Server: 192.168.9.2
```

**链路是：** 应用 → `127.0.0.53`（存根）→ `systemd-resolved`（查缓存）→ `192.168.9.2`（真实上游）。

### 3.4 `curl -v` —— HTTP 全过程

```bash
curl -v http://192.168.9.128/            # 详细
curl -vI https://example.com             # 只取响应头（HEAD）
curl -v http://host/ -o /dev/null -w "%{http_code} %{time_total}\n"
curl -L http://host/                     # 跟随重定向
curl --resolve www.x.com:443:1.2.3.4 https://www.x.com/   # 强制指定 IP
```

**输出四类前缀：**

| 前缀 | 含义 |
|---|---|
| `*` | curl 自己的信息（连接、TLS、耗时） |
| `>` | **发出的请求** |
| `<` | **收到的响应** |
| 无前缀 | 响应正文 |

**实测（本地 80 端口）：**

```
* Connected to 192.168.9.128 (192.168.9.128) port 80
> GET / HTTP/1.1
> Host: 192.168.9.128
> User-Agent: curl/8.5.0
> Accept: */*
>
* HTTP 1.0, assume close after body
< HTTP/1.0 200 OK
< Server: SimpleHTTP/0.6 Python/3.12.3
< Content-type: text/html; charset=utf-8
< Content-Length: 644
<
```

**关键行：**

| 行 | 意义 |
|---|---|
| `> GET / HTTP/1.1` | 方法、路径、版本 |
| `> Host: 192.168.9.128` | **Host 头**——虚拟主机的关键，同一 IP 靠它区分站点 |
| `< HTTP/1.0 200 OK` | 状态码 |
| `* HTTP 1.0, assume close after body` | 没有 keep-alive，响应完就断开 |

**常见退出码：**

| 码 | 含义 |
|---|---|
| `6` | 无法解析主机名 |
| `7` | 连接被拒绝（端口没开） |
| `28` | 超时 |
| `35` | TLS 握手失败 |
| `60` | 证书验证失败 |

### 3.5 `tcpdump` —— 抓包

```bash
sudo tcpdump -i ens33 -n -vv port 53 -c 6          # 实时抓
sudo tcpdump -i any -n port 80
sudo tcpdump -i ens33 -n -w /tmp/x.pcap port 53    # 存文件
sudo tcpdump -r /tmp/x.pcap -n -vv                 # 读文件
sudo tcpdump -i ens33 -n 'host 192.168.9.2 and port 53'
```

| 参数 | 含义 |
|---|---|
| `-i 网卡` | 抓哪个接口（`any` 抓全部） |
| `-n` | **不解析主机名/端口名**（不加会自己发 DNS 查询，还可能卡住） |
| `-nn` | 连端口名也不解析 |
| `-vv` | 更详细的协议解析 |
| `-c N` | 抓 N 个包就停 |
| `-w 文件` | 写入 pcap（Wireshark 可打开） |
| `-r 文件` | 读 pcap |
| `-A` | 以 ASCII 显示内容（看 HTTP 明文） |
| `-X` | 十六进制 + ASCII |

**注意：`-n` 不加会有副作用**——`tcpdump` 为了显示主机名会去查 DNS，产生额外流量甚至递归卡住。

## 四、DNS 抓包全过程（07 的核心产出）

```bash
sudo resolvectl flush-caches                       # 窗口 1：清缓存
sudo tcpdump -i ens33 -n -vv port 53 -c 6          # 窗口 2：抓包
dig www.wikipedia.org +short                       # 窗口 1：触发查询
```

**抓到 6 个包：**

```
04:40:11.981889 192.168.9.128.33824 > 192.168.9.2.53: [bad udp cksum] 23656+ A? ubuntulearn.localdomain. (41)
04:40:11.982175 192.168.9.128.42149 > 192.168.9.2.53: [bad udp cksum] 3873+ AAAA? ubuntulearn.localdomain. (41)
04:40:11.995163 192.168.9.2.53 > 192.168.9.128.42149: [udp sum ok] 3873 NXDomain q: AAAA? ubuntulearn.localdomain. 0/0/0
04:40:12.401005 192.168.9.2.53 > 192.168.9.128.33824: [udp sum ok] 23656*- q: A? ubuntulearn.localdomain. 1/0/0 ubuntulearn.localdomain. A 192.168.9.128
04:40:18.351464 192.168.9.128.39231 > 192.168.9.2.53: [bad udp cksum] 20222+ A? www.wikipedia.org. (35)
04:40:18.363580 192.168.9.2.53 > 192.168.9.128.39231: [udp sum ok] 20222 q: A? www.wikipedia.org. 1/6/12 www.wikipedia.org. A 199.16.158.9 ns: org. NS ...
```

### 4.1 先分清噪音和正事

| 包 | 内容 | 身份 |
|---|---|---|
| 1–4 | `ubuntulearn.localdomain` 的 A/AAAA | **噪音**——系统解析自己主机名 |
| 5–6 | `www.wikipedia.org` | **我们的 dig** |

**前 4 个包为什么出现**：`resolv.conf` 里 `search localdomain`，解析裸主机名 `ubuntulearn` 时自动补后缀 → 查 `ubuntulearn.localdomain`。

- `AAAA?` → `NXDomain`（没有 IPv6 记录）
- `A?` → `192.168.9.128`（本机名解析到自己）

### 4.2 请求包逐字段读

```
192.168.9.128.39231 > 192.168.9.2.53: 20222+ A? www.wikipedia.org. (35)
```

| 字段 | 含义 |
|---|---|
| `192.168.9.128.39231` | 源 IP.源端口，**端口随机**（防缓存投毒） |
| `192.168.9.2.53` | 目的 IP.端口 53 |
| `20222` | **DNS 事务 ID**，请求应答靠它配对 |
| `+` | **RD 位**（Recursion Desired，要递归查询） |
| `A?` | 查询类型 `A`，`?` 表示这是问题 |
| `(35)` | 报文长度 |

### 4.3 应答包逐字段读

```
192.168.9.2.53 > 192.168.9.128.39231: 20222 q: A? www.wikipedia.org. 1/6/12 www.wikipedia.org. A 199.16.158.9 ns: org. NS ...
```

| 字段 | 含义 |
|---|---|
| `20222` | **与请求同 ID** → 配对成功 |
| `q:` | QR 位置位 = 这是应答 |
| **`1/6/12`** | **ANSWER / AUTHORITY / ADDITIONAL 条数** |
| `A 199.16.158.9` | 答案（1 条 A 记录） |
| `ns: org. NS ...` | 6 条 `org` 域权威服务器（AUTHORITY） |
| `ar: ...` | 12 条这些 NS 的 A/AAAA（ADDITIONAL） |

**`1/6/12` 是读懂 DNS 应答的钥匙**——不只给答案，还附带"`org` 域的权威是谁、它们 IP 是多少"，这就是 DNS 的层级结构。

### 4.4 三个技术细节

**① `[bad udp cksum]` 不是错误**

现代网卡有 **checksum offload**：内核把校验和交给网卡算，所以 `tcpdump` 在内核层看到的出站包校验和是空的。

**判别特征：出站包报 `bad`、入站包报 `ok`** → 一定是 offload 假象，忽略。

**② `ttl 64` vs `ttl 128` 能反推对端系统**

| 方向 | TTL | 推断 |
|---|---|---|
| 出站 | 64 | Linux 默认 |
| 入站 | **128** | **Windows 默认** |

说明 `192.168.9.2` 这个 DNS 转发跑在**你的 Windows 宿主机**上（VMware NAT 服务）。

**③ 源端口随机 + 事务 ID 随机 = 防 DNS 缓存投毒**

攻击者要伪造应答，必须同时猜中源端口和 ID，两者都随机化后几乎不可能。

## 六、`/etc/services` 与服务名

`ss` 不加 `-n` 时显示 `ssh`、`http` 而不是 `22`、`80`，依据是 `/etc/services`：

```
ssh             22/tcp
http            80/tcp
https           443/tcp
domain          53/udp
```

**`lsof` 默认解析端口名，`ss` 加 `-n` 则不解析。**

| 想看到 | 参数 |
|---|---|
| 端口显示数字 | `ss -n` / `lsof -P` |
| 禁止解析主机名 | `ss -n` / `lsof -n` |
| 全部数字化 | `ss -nn` / `lsof -Pn` |

**排查一律加 `-n`**：你关心的是数字，不是名字解析对不对。

## 七、重大发现：本机没有真实外网，DNS 被劫持

### 7.1 证据链

**① 三个 DNS 给的答案互相矛盾且都不对：**

| 查询源 | `www.wikipedia.org` 返回 |
|---|---|
| 本地 `192.168.9.2` | `199.16.158.9`（Twitter 段） |
| `8.8.8.8`（Google） | `31.13.112.9`（**Facebook 段**） |
| `1.1.1.1`（Cloudflare） | `31.13.106.4`（**Facebook 段**） |

Wikipedia 真实地址在 `208.80.154.x`。**三个都不是。**

**② 伪造的 AAAA 记录**：`2001::1`——`2001::/32` 是 Teredo 隧道段，不可能给维基百科。

**③ 出站 443 超时**：`Connection timed out after 15003 milliseconds`。

**④ IPv6 无路由**：`Network is unreachable`。

### 7.2 结论（已修正）

> **这台虚拟机的外网是通的**（百度等站点解析正确、TLS 握手成功）。
> **但被封锁的域名（如 `www.wikipedia.org`）会拿到伪造的 DNS 应答，且连不上。**

**⚠️ 修正记录**：本实验最初根据"维基百科连不上"推断成"没有真实互联网出口"，**这是错的**——过度推断。用 `www.baidu.com` 一测就推翻：

```
* IPv4: 180.101.51.40, 180.101.51.157
* Connected to www.baidu.com (180.101.51.40) port 443
* TLSv1.3 (OUT), TLS handshake, Client hello (1)
```

**教训：判断"网络不通"必须用一个确定可达的目标做对照，不能只凭一个失败的目标下结论。**

### 7.3 怎么验证 DNS 是否被劫持（方法论）

| 手段 | 说明 |
|---|---|
| 多 DNS 交叉验证 | `dig @8.8.8.8` / `@1.1.1.1` / 本地，三者不一致即可疑 |
| `dig +trace` | 从根服务器逐级查，被劫持时无法完成 |
| **TLS 证书验证** | **最硬的证据**：`curl -vI https://域名` 看证书 `subject` 是否匹配。DNS 可骗，证书不可骗（除非忽略警告） |
| `curl --resolve` | 强制指定 IP 但保留 Host/SNI，验证"同一个 IP 是不是真的那个站" |

### 7.3 对后续实验的影响（**重要**）

| 实验 | 影响 |
|---|---|
| 08 nginx 静态站 + 反代 | ✅ 不受影响（本地回环/内网即可） |
| 09 防火墙 | ✅ 不受影响 |
| 10 自建 DNS（dnsmasq） | ✅ 可做（本地解析自己配的域名，不依赖上游） |
| 11 静态 IP | ✅ 不受影响 |
| 12 MySQL / 13 备份 / 14 rsync | ✅ 本地即可 |
| 16–19 Docker | ⚠️ **拉镜像可能失败**，需配国内镜像加速器（`/etc/docker/daemon.json`） |
| 23 Prometheus | ⚠️ 同样依赖拉镜像，同上 |
| **25 云主机 / 26 HTTPS** | ⚠️ 需选**国内**云厂商与域名；Let's Encrypt 的 HTTP-01 校验需能外部访问，可行但需注意 |

**结论：阶段 A–B 全部可做，阶段 C（Docker）需先配镜像加速器。**

## 八、踩坑清单

| # | 坑 | 说明 / 正确做法 |
|---|---|---|
| 1 | `sudo cmd &` 直接后台化 | sudo 要读密码但没有终端 → 进程被 `SIGTTIN` 停住（`Stopped (tty input)`）。正确：**先 `sudo -v` 拿凭证，再 `sudo nohup cmd &`** |
| 2 | `kill %1` 杀不掉 Stopped 的作业 | `SIGTERM` 对停止态进程只是挂起。**必须 `kill -9`**（内核直接终止） |
| 3 | 终端回显错乱（粘贴文字删不掉） | `Ctrl+Z` 打断 sudo 密码读取会留下关闭 echo 的状态。**`Ctrl+U` 清行**，或 **`stty sane` / `reset`** 复位 |
| 4 | 前台服务占住终端 | `Ctrl+Z` 暂停 → `bg` 转后台 → `jobs -l` 确认 `Running`；彻底脱离用 `nohup` / `setsid` |
| 5 | 以为 `resolv.conf` 里的 `127.0.0.53` 是配错了 | 那是 `systemd-resolved` 的**存根**，真实上游看 `resolvectl status` |
| 6 | `dig` 结果对不上 | **先核对域名拼写**（本次把 `example.com` 打成了 `exmaple.com`，一个真实存在的另一域名） |
| 7 | 抓包抓到一堆无关 DNS | `search localdomain` 会让裸主机名被补后缀查询。**先分噪音再分析** |
| 8 | 把 `[bad udp cksum]` 当故障 | checksum offload 假象：**出站 bad、入站 ok** 就是正常 |
| 9 | `tcpdump` 不加 `-n` | 它会去解析主机名，产生额外查询甚至卡住 |
| 10 | `python3 -m http.server` 在 home 目录启动 | **会把 `.bash_history`、`.ssh/` 全暴露**。必须 `--directory` 指定目录 |
| 11 | 以为 `Send-Q` 是"发送数据量" | LISTEN 状态下是 **backlog 上限** |
| 12 | 以为绑 `0.0.0.0` 和 `127.0.0.1` 一样 | 前者所有网卡可达，后者仅本机。**这是安全配置的核心区别** |
| 13 | 用 `ss` 看不到进程 | `-p` 需要 root，加 `sudo` |
| 14 | 以为 `curl` 失败就是网络不通 | 先看退出码：`6` DNS / `7` 拒绝 / `28` 超时 / `35` TLS / `60` 证书 |

## 九、命令详解（本项首次出现的命令与参数）

### 9.1 `ip` 子命令全家

```bash
ip a / ip addr              # 地址
ip r / ip route             # 路由
ip route get <目标>          # 查某目标走哪条路
ip neigh                    # ARP/邻居
ip link                     # 网卡状态
ip -br a                    # 一行式简表
ip -4 a / ip -6 a           # 只看 IPv4 / IPv6
```

**`ip` 取代了老的 `ifconfig` / `route` / `arp`**（`net-tools` 包默认已不装）。

### 9.2 `lsof -i`

```bash
sudo lsof -i :80            # 谁占 80 端口
sudo lsof -i tcp:80
sudo lsof -i udp:53
sudo lsof -P -n -i          # 端口/主机名都不解析
```

**`lsof -i` = 列出网络连接相关的文件描述符**，和 `ss` 互为交叉验证。

### 9.3 `printf` / `command -v`（复用 04 的知识）

```bash
for c in ip ss dig curl tcpdump nc traceroute; do
  printf "%-12s %s\n" "$c" "$(command -v $c || echo '未安装')"
done
```

`printf "%-12s"` = 左对齐占 12 字符；`command -v` 查命令路径（POSIX 标准，优于 `which`）。

### 9.4 `stty sane` / `reset`

```bash
stty sane      # 恢复终端 termios 设置（回显、换行等）
reset          # 更彻底：清屏 + 重置终端类型
```

**终端"打字看不见"或"文字删不掉"的万能复位。**

### 9.5 `bg` / `fg` / `jobs` / `disown`

```bash
Ctrl+Z         # 暂停前台进程
bg             # 把暂停的作业放后台继续
fg %1          # 调回前台
jobs -l        # 列出作业 + PID + 状态
disown -h %1   # 从作业表移除，退出 shell 不被杀
```

### 9.6 `sysctl`

```bash
sysctl net.core.somaxconn            # 查内核参数
sudo sysctl -w net.core.somaxconn=4096   # 临时改
sudo sysctl -p                       # 重载 /etc/sysctl.conf
```

### 9.7 `nc`（netcat，本文未实测但必备）

```bash
nc -zv 192.168.9.128 22      # 测端口通不通
nc -l 9999                   # 监听 9999
nc 192.168.9.128 80          # 手动连过去发请求
```
