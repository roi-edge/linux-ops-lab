# 04 进程与资源排查

> 实验日期：2026-10-28
> 环境：Ubuntu 24.04.5 LTS（`ubuntulearn` / `192.168.9.128`），**2 核 / 3.8Gi 内存 / 无 swap**

## 一、目标与验收

**做：** 跑一个 `yes > /dev/null &` 占满 CPU，用 `top` / `ps aux` / `lsof -p` 找出它并杀掉

**验收：** 能逐列解释 `top` 的 **load average**、**wa**、**si** 分别代表什么

**本次结论：** 四道口头验收题全部通过（见第九节）。

## 二、环境基线（必须先记，否则看不出变化）

```bash
nproc          # 2
free -h        # 3.8Gi 总，无 swap
uptime         # load average: 0.00, 0.06, 0.07
top -bn1 | head -5
```

基线数据：

| 指标 | 空闲时 |
|---|---|
| load average | `0.00, 0.06, 0.07` |
| `%Cpu(s)` | `0.0 us, 0.0 sy, 100.0 id` |
| `Tasks` | `1 running` |
| 内存 | 606Mi 已用，3.2Gi 可用 |
| swap | **0B（没有）** |

> **无 swap 的含义**：内存耗尽时不会换出到磁盘缓冲，会直接触发 OOM killer 杀进程。后面做 Prometheus（23）时要注意。

## 三、实测数据（本次真实记录）

| 阶段 | load average (1/5/15) | `%Cpu(s)` 关键值 | 备注 |
|---|---|---|---|
| 空闲基线 | 0.00 / 0.06 / 0.07 | id 100.0 | — |
| 1 个 `yes` | 0.66 → 0.69 | us 14.3, sy 38.1, id 47.6 | 1 核跑满，2 核机器 → ≈50% |
| 2 个 `yes` | 1.41 → 1.67 → 接近 2.0 | us 26.1, sy 73.9, id **0.0** | 全核满载 |
| 杀完之后 | 0.11 / 0.58 / 0.47 | id 100.0 | 1min 先降，5/15min 滞后 |
| 4 路 4k 直接 IO | 1.58 / 0.44 / 0.36 | us 2.9, sy 48.6, **wa 5.7**, id 0.0, **si 42.9** | in≈10000, cs≈14500, bo≈45000, b 列 1~3 |
| 清理后 | 0.02 / 0.16 / 0.32 | id 100.0 | — |

**关键观察：**

1. **`ps aux` 的 `%CPU` 是 99.9**（一个 `yes` 吃满一个核），而不是 50。因为 `ps` 的 `%CPU` 是**进程生命周期内的平均值**，且**以单核为 100% 计**；`top` 的 `%Cpu(s)` 才是全机瞬时值
2. **`yes` 的 `sy` 远高于 `us`**——它每个字符都调一次 `write()`
3. **load average 的滞后性**：进程杀掉后 `1min` 立刻掉到 0.11，`5min` 还有 0.58
4. **IO 压力下 `si` 能飙到 42.9%**，这是本次最意外的发现

## 四、操作步骤

> 约定：每个命令块标注执行身份。

### 4.1 制造 CPU 负载

```bash
# 身份：madrough
madrough@ubuntulearn:~$ yes > /dev/null &
[1] 2306
```

| 部分 | 作用 |
|---|---|
| `yes` | 无限循环输出 `y`，永不停止 |
| `>` | 重定向标准输出 |
| `/dev/null` | 黑洞设备，写入内容全部丢弃 |
| `&` | 放到后台，不占住终端 |

**为什么必须重定向**：不重定向的话满屏 `y` 会把 SSH 卡死。**烧的是 CPU（不停拼字符串+写），`/dev/null` 只是把结果扔掉。**

> **`yes` 只吃一个核**。2 核机器上只能到 50%，要跑满得开 `nproc` 个。

### 4.2 观察变化

```bash
# 身份：madrough
madrough@ubuntulearn:~$ sleep 5; uptime
madrough@ubuntulearn:~$ top -bn1 | head -5
madrough@ubuntulearn:~$ jobs -l
```

`top -bn1` = 批处理模式（`-b`）跑 1 次（`-n1`）后退出，适合脚本和非交互场景。

### 4.3 用 `ps` 定位

```bash
# 身份：madrough
madrough@ubuntulearn:~$ ps aux --sort=-%cpu | head -5
```

| 部分 | 含义 |
|---|---|
| `a` | 所有用户的进程 |
| `u` | 用户友好格式 |
| `x` | 包含没有控制终端的进程 |
| `--sort=-%cpu` | 按 CPU 降序（负号=降序） |

**`ps aux` 各列：**

| 列 | 含义 |
|---|---|
| `USER` | 启动者 |
| `PID` | 进程 ID |
| `%CPU` | CPU 占用（**生命周期平均值**，以单核 100% 计，可超 100） |
| `%MEM` | 内存占比 |
| `VSZ` | 虚拟内存（含未分配的） |
| `RSS` | **常驻物理内存**（真实占用） |
| `TTY` | 关联终端；`?` = 无终端 |
| `STAT` | `R` 运行、`S` 睡眠、**`D` 不可中断（等 IO）**、`Z` 僵尸、`T` 停止 |
| `START` | 启动时间 |
| `TIME` | 累计 CPU 时间（不是时钟时间） |
| `COMMAND` | 命令 |

```bash
# 身份：madrough
madrough@ubuntulearn:~$ ps -p 2306 -o pid,ppid,user,%cpu,%mem,stat,etime,cmd
```

`-o` 自选列：`ppid` 父进程（能看出是哪个 shell 生的）、`etime` 已运行时长。

```bash
# 身份：madrough
madrough@ubuntulearn:~$ pgrep -a yes
2306 yes
```

`-a` 显示完整命令行。

### 4.4 用 `lsof -p` 看它打开了什么

```bash
# 身份：madrough
madrough@ubuntulearn:~$ sudo lsof -p 2306
```

实测输出（关键行）：

```
COMMAND  PID     USER   FD   TYPE DEVICE SIZE/OFF   NODE NAME
yes     2306 madrough  cwd    DIR  252,0     4096 524360 /home/madrough
yes     2306 madrough  txt    REG  252,0    35208  45071 /usr/bin/yes
yes     2306 madrough  mem    REG  252,0  2129424  39373 /usr/lib/x86_64-linux-gnu/libc.so.6
yes     2306 madrough    0u   CHR  136,0      0t0      3 /dev/pts/0
yes     2306 madrough    1w   CHR    1,3      0t0      5 /dev/null      ← 输出被丢进黑洞
yes     2306 madrough    2u   CHR  136,0      0t0      3 /dev/pts/0
```

**FD 列的含义**：`cwd` 当前目录、`txt` 程序本体、`mem` 内存映射、`0u/1w/2w` 标准输入/输出/错误，`u` 读写、`w` 写、`r` 读。

**`1w -> /dev/null` 这一行直接证实了重定向生效**。

### 4.5 用 `/proc` 看进程活体档案

```bash
# 身份：madrough
madrough@ubuntulearn:~$ ls -l /proc/2306/cwd
madrough@ubuntulearn:~$ tr '\0' ' ' < /proc/2306/cmdline; echo
madrough@ubuntulearn:~$ head -6 /proc/2306/status
madrough@ubuntulearn:~$ ls -l /proc/2306/fd/
```

实测 `status`：

```
Name:   yes
Umask:  0002
State:  R (running)
Tgid:   2306
Ngid:   0
Pid:    2306
```

**`/proc/<PID>/` 常用路径：**

| 路径 | 内容 |
|---|---|
| `cmdline` | 启动命令（**`\0` 分隔**，要 `tr '\0' ' '` 才可读） |
| `cwd` | 当前工作目录（软链） |
| `exe` | 可执行文件路径（软链） |
| `fd/` | 所有打开的文件描述符 |
| `status` | 名称、状态、内存、UID、线程数、**Umask** |
| `environ` | 环境变量 |

> `Umask: 0002` 正好印证实验 02 的结论：普通用户默认 umask 是 `002`。

### 4.6 先礼后兵地杀掉

```bash
# 身份：madrough
madrough@ubuntulearn:~$ kill 2306          # 默认 SIGTERM
madrough@ubuntulearn:~$ sleep 2; jobs -l
[1]+  Terminated              yes > /dev/null
madrough@ubuntulearn:~$ ps -p 2306
    PID TTY          TIME CMD                   # 只剩表头 = 已死
```

### 4.7 占满全部核心，用 `kill -9` 清场

```bash
# 身份：madrough
madrough@ubuntulearn:~$ yes > /dev/null &
yes > /dev/null &
madrough@ubuntulearn:~$ sleep 10; uptime && top -bn1 | head -3
# load average 逼近 2.0，id 0.0

madrough@ubuntulearn:~$ kill -9 2379
madrough@ubuntulearn:~$ jobs -l
[1]-  2379 Killed                  yes > /dev/null     ← Killed = SIGKILL 的痕迹
[2]+  2380 Running                 yes > /dev/null &

madrough@ubuntulearn:~$ pkill yes
madrough@ubuntulearn:~$ pgrep -a yes                     # 空
```

**`Terminated` vs `Killed`**：前者是 `SIGTERM`（可捕获、可清理），后者是 `SIGKILL`（内核强杀，无机会反应）。

### 4.8 制造 IO 压力看 `wa` 和 `si`

小文件写因为太快看不到效果，正确姿势是**小块 + 直接 IO + 并发**：

```bash
# 身份：madrough
madrough@ubuntulearn:~$ sudo chown madrough:madrough /data   # 否则写不进去
madrough@ubuntulearn:~$ for i in 1 2 3 4; do dd if=/dev/zero of=/data/iotest$i bs=4k count=300000 oflag=direct &
done
madrough@ubuntulearn:~$ vmstat 1 8
madrough@ubuntulearn:~$ top -bn1 | head -3
```

实测 `vmstat`（部分）：

```
 r  b   swpd   free   buff  cache   si   so    bi    bo   in   cs us sy id wa st
 1  3      0 3091568  40244 481668    0    0   140   322  478    0  4 12 83  0  0
 4  0      0 3091568  40244 481668    0    0     0 45664 10266 14480  1 88  0 11  0  0
 1  3      0 3091568  40244 481668    0    0     0 44232 9914 14145  1 88  0 11  0  0
```

实测 `top`：

```
%Cpu(s):  2.9 us, 48.6 sy,  0.0 id,  5.7 wa,  0.0 hi, 42.9 si
```

**解读**：`b` 一度 1~3（进程在等 IO）、`bo` ~45MB/s、`wa` 5.7、**`si` 42.9**。

清理：

```bash
# 身份：madrough
madrough@ubuntulearn:~$ rm -f /data/iotest*
madrough@ubuntulearn:~$ df -h /data
```

> **第一次尝试失败的原因**：`bs=1M count=400 conv=fsync` 在一两秒就写完了，`vmstat` 采样根本抓不到 `wa`。VM 的虚拟盘落在宿主机 SSD 上，够快。**小块 + 直接 IO + 并发**才把压力堆出来。

## 五、原理：`top` 那一行到底怎么读

```
top - 03:50:18 up 52 min, 1 user,  load average: 1.58, 0.44, 0.36
Tasks: 240 total, 4 running, 236 sleeping, 0 stopped, 0 zombie
%Cpu(s):  2.9 us, 48.6 sy,  0.0 ni,  0.0 id,  5.7 wa,  0.0 hi, 42.9 si,  0.0 st
MiB Mem : 3868.0 total, 3009.6 free, 605.2 used, 485.2 buff/cache
```

### 5.1 load average

**不是 CPU 使用率**，而是**运行队列中的任务数**（`R` 运行/可运行 + `D` 不可中断睡眠）的指数滑动平均，三个数分别是过去 1/5/15 分钟的均值。

2 核机器：

| load | 含义 |
|---|---|
| `0.5` | 平均只有半个任务，一半算力闲置 |
| `2.0` | 正好吃满，无排队 |
| `4.0` | 超载一倍，每任务只拿一半 CPU |
| `> 核数 × 2` | 明显卡顿 |

**两个坑：**

1. **包含 `D` 状态 → IO 慢也会推高 load**。硬盘快挂或 NFS 卡住时 load 能冲到 10+，而 CPU 空闲 90%。所以 **load 高要先看 `wa` 和 `b`**，分清是 CPU 不够还是 IO 太慢
2. **三个数看趋势**：1min 高 15min 低 = 突发；三个都高 = 持续过载；1min 低 15min 高 = 刚恢复

### 5.2 `%Cpu(s)` 九个字段

| 字段 | 全称 | 含义 |
|---|---|---|
| `us` | user | 用户态代码（应用自己算的） |
| `sy` | system | 内核态代码（系统调用、驱动、内存管理） |
| `ni` | nice | 调整过优先级的用户进程 |
| `id` | idle | 完全空闲 |
| `wa` | iowait | **CPU 空闲但正在等 IO** |
| `hi` | hardware irq | 硬中断处理 |
| `si` | software irq | **软中断处理** |
| `st` | steal | 被虚拟化宿主抢占的时间（虚机特有） |
| `gu` | guest | 给客户机跑的时间（vmstat 里才有） |

### 5.3 `wa`（iowait）

- **CPU 空闲但至少有一个进程在等磁盘 IO** 的时间占比
- 不是"CPU 在干活"，而是**闲着也干不了别的**
- `wa` 高 + `id` 低 = 瓶颈在存储，**加 CPU 无用**
- 对应进程状态是 **`D`（不可中断睡眠）**，`kill -9` 也杀不掉，只能等 IO 完成或重启
- **为什么有时 `wa` 偏低**：只有"CPU 完全空闲且有 IO 等待"才计入；如果 CPU 同时在跑别的进程，那段时间算 busy，`wa` 就显不出来（本次 `wa` 仅 5.7 但 `bo` 达 45MB/s 就是这个原因）

### 5.4 `si`（softirq）——与 `vmstat` 的 `si` 完全不同

**`top` 的 `si` = software interrupts**，CPU 处理软中断的时间占比。

背景：硬件中断分两半——

| 阶段 | 干什么 | 要求 |
|---|---|---|
| 上半部（硬中断 `hi`） | 立刻响应硬件，做最少的事 | 必须极快 |
| 下半部（**软中断 `si`**） | 慢慢处理实际工作 | 可延后 |

走软中断的事：网络包收发、**块设备 IO 完成通知**、定时器、RCU。

**本次为什么飙到 42.9**：4 路并发 × 4KB × `oflag=direct`，每秒上万次 IO 完成事件，每次都要软中断处理。配合 `in≈10000`（中断/秒）、`cs≈14500`（上下文切换/秒）完全对得上。而跑 `yes` 时 `si` 是 `0.0`——它只死循环调 `write()`，没有 IO 事件。

**`si` 高的典型场景**：网络包风暴（DDoS、广播风暴）、大量小块 IO、驱动 bug。

**⚠️ `vmstat` 的 `si` 是另一回事：swap in（从 swap 换入的速率，KB/s）。** 两个都叫 `si`，毫不相干。面试问"top 的 si"要答**软中断**。

### 5.5 `us` vs `sy`

| 指标 | 含义 | 高了说明 |
|---|---|---|
| `us` 高 | 应用自己的代码在算 | 算法/业务逻辑吃 CPU，优化代码或加核 |
| `sy` 高 | 内核在替你干活（syscall、IO、驱动） | 系统调用过多、IO 密集、虚拟化开销、驱动问题 |

`yes` 的 `sy`(73.9) > `us`(26.1)：逻辑本身几乎不耗时，时间全在"进内核 → 搬数据 → 回用户态"的来回上。

**经验阈值**：`sy` 持续 > 30% 通常不正常（IO 密集型场景除外）。

### 5.6 `Tasks` 那行

```
240 total, 4 running, 236 sleeping, 0 stopped, 0 zombie
```

- `running` 包含真正在跑的和排队等 CPU 的
- `zombie` > 0 要查：父进程没回收子进程，`ps aux | grep Z` 找，父进程退出才能清

### 5.7 `st`（steal）——虚机特有

被宿主机（hypervisor）抢走的 CPU 时间。**`st` 高 = 宿主机超卖，你这台虚机被别人拖累**，换宿主机或升配置才有用，虚机内部怎么优化都没意义。

## 六、信号与杀进程

```bash
kill <PID>          # 默认 SIGTERM(15)，请它退出
kill -9 <PID>       # SIGKILL，内核强杀
kill -l             # 列出所有信号
pkill <名字>        # 按名字批量
pkill -f "<命令行>" # 按完整命令行匹配
pgrep -a <名字>     # 查（相当于 ps | grep）
pgrep -x <名字>     # 精确匹配进程名
killall <名字>      # 按名字（需完全匹配）
```

| 信号 | 编号 | 行为 |
|---|---|---|
| `SIGHUP` | 1 | 终端断开时发；很多守护进程收到会重读配置 |
| `SIGINT` | 2 | 相当于 `Ctrl+C` |
| `SIGKILL` | 9 | **不可捕获、不可忽略**，内核强杀 |
| `SIGTERM` | 15 | **默认**，请求退出，进程可捕获做清理 |
| `SIGSTOP` | 19 | 暂停（不可捕获） |

**正确姿势：先 `kill`（TERM），无效再 `kill -9`。**

直接 `-9` 的代价：数据库丢未落盘事务、临时文件堆积、锁文件残留导致下次启动失败。

**唯一例外**：进程处于 `D` 状态时 `kill -9` 也无效，只能等 IO 或重启。

## 七、踩坑清单

| # | 坑 | 说明 |
|---|---|---|
| 1 | `pgrep dd` 匹配到了 `kthreadd`、`ipv6_addrconf` | `pgrep` 默认是**正则子串匹配**，要精确匹配加 `-x` |
| 2 | `ps aux \| grep yes` 里总有一条多余结果 | `grep` 进程自己也在结果里；用 `pgrep` 或 `grep [y]es` |
| 3 | 以为 `ps` 的 `%CPU` 就是实时占用 | 它是**生命周期平均值**，且以单核 100% 计，可超 100 |
| 4 | 以为 1 个 `yes` 能把 2 核机器 CPU 打到 100% | 只能打满 1 核，`%Cpu(s)` 最多 50%（`id` 50） |
| 5 | 用 `dd bs=1M` 想看 `wa`，结果全程 0 | 盘太快，一两秒就写完；要**小块 + `oflag=direct` + 并发** |
| 6 | `dd` 写 `/data` 报 `Permission denied` | `/data` 属主是 root、755，普通用户无写权限；`chown` 或 `sudo` |
| 7 | 把 `top` 的 `si` 当成 swap in | `top.si` = 软中断；`vmstat.si` 才是 swap in |
| 8 | 认为 load 高就是 CPU 不够 | `D` 状态（等 IO）也计入 load，要看 `wa`/`b` 才能定性 |
| 9 | 直接 `kill -9` | 先 `SIGTERM`，让它有机会清理 |
| 10 | `pkill -f python` 误杀一片 | `-f` 匹配整条命令行，先用 `pgrep -af` 确认命中列表 |
| 11 | 退出 SSH 后 `yes` 也死了 | 后台进程是 shell 子进程，退出时收 `SIGHUP`；用 `nohup`/`setsid`/`disown` 脱离 |
| 12 | `cat /proc/<PID>/cmdline` 出来一团乱码 | 参数用 `\0` 分隔，需要 `tr '\0' ' '` |

## 八、命令详解（本项首次出现的命令与参数）

### 8.1 `nproc` / `free` / `lscpu`

```bash
nproc              # 可用 CPU 核数
nproc --all        # 全部核数
free -h            # 内存，人类可读
free -m            # 以 MB 显示
lscpu              # CPU 型号、架构、核数详情
```

`free -h` 各列：`total` 总量、`used` 已用、`free` 完全空闲、`shared` 共享内存、`buff/cache` 缓存占用（**可回收，不算真占用**）、`available` 实际可用（含可回收部分）。

### 8.2 `top` 的参数

```bash
top                # 交互模式，q 退出
top -bn1           # -b 批处理模式，-n1 只跑 1 次后退出
top -p 2306        # 只看指定 PID
top -o %CPU        # 按 CPU 排序
top -d 2           # 每 2 秒刷新
```

交互模式下的按键：`P` 按 CPU 排序、`M` 按内存排序、`k` 杀进程、`1` 展开每个核、`c` 显示完整命令行、`q` 退出。

### 8.3 `ps` 的三种风格

```bash
ps aux                       # BSD 风格（无连字符）
ps -ef                       # System V 风格
ps -p 2306 -o pid,ppid,stat,cmd   # 自定义列
ps aux --sort=-%cpu          # 排序
ps -eo pid,%cpu,%mem,cmd --sort=-%mem | head
```

**`stat` 状态码**：`R` 运行、`S` 可中断睡眠、`D` 不可中断（等 IO）、`Z` 僵尸、`T` 停止、`I` 空闲内核线程。后面可能跟 `<` 高优先级、`N` 低优先级、`s` 会话首进程、`l` 多线程。

### 8.4 `jobs` / `fg` / `bg` / `disown`

```bash
jobs -l        # 列出当前 shell 的后台作业（含 PID）
fg %1          # 把作业 1 调到前台
bg %1          # 让暂停的作业在后台继续
disown -h %1   # 从作业表移除，避免收到 SIGHUP
```

### 8.5 `pgrep` / `pkill`

```bash
pgrep -a yes        # -a 显示命令行
pgrep -x dd         # -x 精确匹配进程名（不含子串）
pgrep -u madrough   # 只看某用户
pgrep -f "python3 app.py"   # -f 匹配完整命令行
pkill yes           # 按名字杀
pkill -9 -f "..."   # 强制杀
```

**⚠️ 默认是正则子串匹配**——`pgrep dd` 会命中 `kthreadd`。要精确用 `-x`。

### 8.6 `kill` 与信号

```bash
kill 2306           # 默认 TERM
kill -15 2306       # 显式 TERM
kill -9 2306        # KILL
kill -l             # 列出全部信号
kill -TERM 2306     # 用名字也行
```

### 8.7 `lsof`

```bash
sudo lsof -p 2306        # 某进程打开的所有文件
sudo lsof -i :22         # 谁占着 22 端口
sudo lsof /data/x.txt    # 谁打开着这个文件（删不掉时用）
sudo lsof -u madrough    # 某用户打开的文件
sudo lsof +D /data       # 某目录下被打开的文件
sudo lsof -i -P -n       # 网络连接（-P 不转换端口名，-n 不解析IP）
```

**经典用途**：`df` 显示磁盘满但 `du` 找不到大文件 → 有进程还开着已删除的文件 → `lsof +L1` 找出来，重启那个进程就释放。

### 8.8 `dd`

```bash
dd if=/dev/zero of=/data/iotest bs=1M count=400 conv=fsync
dd if=/dev/zero of=/data/x bs=4k count=300000 oflag=direct
dd if=/dev/sdb of=/dev/null bs=1M        # 测读速度
```

| 参数 | 含义 |
|---|---|
| `if=` | 输入文件/设备 |
| `of=` | 输出文件/设备 |
| `bs=` | 每次读写的块大小 |
| `count=` | 次数 |
| `conv=fsync` | 结束时强制刷盘 |
| `oflag=direct` | 绕过页缓存，直接和磁盘打交道 |
| `status=progress` | 显示进度 |

> `dd` 是"磁盘毁灭者"之一，`of=` 写成 `/dev/sda` 就完了。执行前务必确认。

### 8.9 `vmstat`

```bash
vmstat 1 6      # 每 1 秒采样，共 6 次
vmstat -s       # 汇总统计
```

列含义：`r` 等 CPU 的进程、`b` 不可中断睡眠、`swpd` 已用 swap、`free` 空闲内存、`buff/cache`、`si/so` **swap in/out**、`bi/bo` 块设备读写、`in` 中断/秒、`cs` 上下文切换/秒、`us/sy/id/wa/st` 同 top。

### 8.10 `tr` / `printf` / `command -v`

```bash
tr '\0' ' ' < /proc/2306/cmdline     # 把空字符换成空格
printf "%-8s %s\n" "$c" "$path"      # 格式化输出，%-8s 左对齐占 8 字符
command -v top                        # 查命令路径（比 which 更标准）
```

- `fmt` 里的 `%s` 是字符串占位，`-8` 表示左对齐最小宽度 8
- `command -v` 是 POSIX 标准，`which` 不是；脚本里用前者

### 8.11 `sleep`

```bash
sleep 5           # 睡 5 秒
sleep 0.5         # 支持小数（GNU coreutils）
```

常用于"等一下再看"的场景，比如 `sleep 5; uptime`。
