## 一、目标与验收

**做：** 输出磁盘/内存/负载/关键服务状态，**超阈值标红**；**退出码有区分**

**验收：** **脚本能在出问题时返回非 0，可被监控调用**

**结论：** 达成，三个退出码全部实测：

```
默认阈值(80/90)     磁盘 90% ≥ 90   → CRIT  退出码 2
DW=85 DC=100        90 ≥ 85         → WARN  退出码 1
DW=95 DC=100        90 < 95         → OK    退出码 0
```

**而且脚本第一次运行就抓到了一个真问题**（磁盘 91%），推动了后面一轮（不成功的）清理 —— **这才是监控脚本的价值：它逼你去处理真实问题。**

## 二、最终状态

### 2.1 脚本 `/usr/local/bin/lab21-healthcheck.sh`（`755 root`，共 33 行）

```bash
#!/bin/bash
# lab21 巡检：磁盘/内存/负载/服务；超阈值标红；退出码 0=OK 1=WARN 2=CRIT
set -uo pipefail
W=0; C=0
g=$'\033[32m'; y=$'\033[33m'; r=$'\033[31m'; n=$'\033[0m'

check() {  # 名称 当前值 警告阈值 严重阈值 单位
  if awk "BEGIN{exit !($2 >= $4)}"; then
    printf '%sCRIT%s %-6s %s%s\n' "$r" "$n" "$1" "$2" "$5"; C=$((C+1))
  elif awk "BEGIN{exit !($2 >= $3)}"; then
    printf '%sWARN%s %-6s %s%s\n' "$y" "$n" "$1" "$2" "$5"; W=$((W+1))
  else
    printf '%sOK%s   %-6s %s%s\n' "$g" "$n" "$1" "$2" "$5"
  fi
}

DISK=$(df --output=pcent / | tail -1 | tr -dc '0-9')
MEM=$(free | awk '/^Mem:/{printf "%.0f", $3/$2*100}')
L1=$(awk '{print $1}' /proc/loadavg); N=$(nproc)
LOAD=$(awk -v l="$L1" -v c="$N" 'BEGIN{printf "%.0f", l/c*100}')

echo "=== $(hostname) $(date '+%F %T') ==="
check 磁盘 "$DISK" "${DW:-80}" "${DC:-90}" '%'
check 内存 "$MEM" "${MW:-85}" "${MC:-95}" '%'
check 负载 "$LOAD" "${LW:-100}" "${LC:-200}" "%(L1=$L1/${N}核)"

for s in nginx mysql dnsmasq ssh cron ufw; do
  st=$(systemctl is-active "$s" 2>/dev/null | head -1)
  [ "$st" = active ] && continue
  printf '%sCRIT%s %-6s %s\n' "$r" "$n" "$s" "${st:-unknown}"; C=$((C+1))
done

echo "--- WARN=$W CRIT=$C ---"
[ "$C" -gt 0 ] && exit 2
[ "$W" -gt 0 ] && exit 1
exit 0
```

### 2.2 阈值可配置

| 环境变量 | 默认 | 含义 |
|---|---|---|
| `DW` / `DC` | 80 / 90 | 磁盘警告 / 严重（%） |
| `MW` / `MC` | 85 / 95 | 内存警告 / 严重（%） |
| `LW` / `LC` | 100 / 200 | 负载警告 / 严重（**按 load÷核数×100 换算**） |

### 2.3 实测输出

```
=== ubuntulearn 2026-11-18 04:27:52 ===
WARN 磁盘 90%
OK   内存 36%
OK   负载 16%(L1=0.31/2核)
--- WARN=1 CRIT=0 ---
```

## 三、操作步骤

### 3.1 摸底（拿到阈值设计依据）

```bash
# 身份：madrough @ ubuntulearn（普通用户；sudo 提权）
madrough@ubuntulearn:~$ df -h / | tail -1        # 91%（已经超 90 严重线）
madrough@ubuntulearn:~$ free -m | head -2 | tail -1   # 3868 总 / 38% 用
madrough@ubuntulearn:~$ nproc; cat /proc/loadavg      # 2 核 / 0.07 0.12 0.10
madrough@ubuntulearn:~$ systemctl is-active nginx mysql dnsmasq ssh cron ufw | tr '\n' ' '
madrough@ubuntulearn:~$ bash --version | head -1      # 5.2.21
```

**`nproc` + `/proc/loadavg` 是"负载阈值"的前提**：load 是"排队任务数"，**2 核上 load=2.0 才是满载**。

### 3.2 写脚本（分两次追加，避免终端粘贴截断）

第一段：`check()` 函数（见 2.1 前 15 行）；第二段：采集 + 服务检查 + 退出码。

**两段之间用 `bash -n` 校验**（只查语法不执行）→ 再 `sudo install -m 755` 装到系统路径。

### 3.3 三档退出码验收

```bash
madrough@ubuntulearn:~$ /usr/local/bin/lab21-healthcheck.sh > /dev/null; echo "默认 退出码=$?"     # 2
madrough@ubuntulearn:~$ DW=85 DC=100 /usr/local/bin/lab21-healthcheck.sh; echo "WARN档 退出码=$?"  # 1
madrough@ubuntulearn:~$ DW=95 DC=100 /usr/local/bin/lab21-healthcheck.sh; echo "OK档 退出码=$?"    # 0
```

**关键点**：`> /dev/null` 之后退出码依然是 2 → **证明退出码和输出无关**，是脚本 `exit 2` 出来的，**监控可以只看退出码**。

## 四、原理

### 4.1 退出码是"给机器看的"，输出是"给人看的"

| 退出码 | 业界惯例（Nagios 插件标准） | 监控动作 |
|---|---|---|
| **0** | OK | 绿色，不通知 |
| **1** | WARNING | 黄色，提醒 |
| **2** | CRITICAL | 红色，立即告警 |
| 3 | UNKNOWN | 脚本自身出错 |

**监控系统（Zabbix / Prometheus 的 textfile collector / Icinga）判断级别，靠的就是这个整数，不是输出里的文字。**

### 4.2 负载为什么要"除以核数"

| load | 2 核机器 | 判断 |
|---|---|---|
| 0.5 | 25% | 轻松 |
| 2.0 | **100%** | **刚好满载** |
| 4.0 | **200%** | 超载一倍（一半任务在排队） |

**不除核数就没法写统一阈值**（8 核机器的 load=4 很健康，2 核机器的 load=4 已经过载）。

### 4.3 bash 不能比小数 —— 用 `awk` 代劳

```bash
[ "0.35" -ge "1" ]        # ❌ 报错：需要整数
awk "BEGIN{exit !(0.35 >= 1)}"   # ✅ 浮点比较；条件不成立 → exit 0
```

**`awk "BEGIN{exit !(条件)}"` 的用法**：

| 部分 | 作用 |
|---|---|
| `BEGIN{}` | 不读输入，直接执行（只做计算） |
| `exit !(条件)` | 条件成立 → `!1` = 0（成功）；不成立 → `!0` = 1（失败） |
| bash 侧 | 用 `if awk …; then` 判断它的退出码 |

### 4.4 ANSI 颜色

```bash
g=$'\033[32m'      # 绿色
printf '%sOK%s\n' "$g" "$n"
```

| 部分 | 含义 |
|---|---|
| `$'...'` | bash 的 **ANSI-C 引用**，让 `\033` 变成真正的 ESC 字符 |
| `\033[32m` | 前景绿；`33`=黄、`31`=红、`0`=复位 |
| 为什么用完要复位 | 否则后面的所有输出都变那个颜色 |

### 4.5 `set -uo pipefail` 的取舍

| 选项 | 这里用不用 | 为什么 |
|---|---|---|
| `-e` | ❌ **不用** | 巡检脚本要**跑完所有检查**再决定退出码；`-e` 会在第一个非 0 处退出 |
| `-u` | ✅ | 引用未定义变量就报错（但 `$((C+1))` 需要先初始化 `C=0`） |
| `-o pipefail` | ✅ | 管道任一环失败都算失败（`df | tail`、`systemctl | head` 都受益） |

**`-e` 和"要汇总所有结果"是矛盾的** —— 这是本项对实验 13/19 脚本习惯的一个例外。

### 4.6 取值技巧（三行采集）

| 需求 | 命令 | 关键 |
|---|---|---|
| 磁盘百分比数字 | `df --output=pcent / \| tail -1 \| tr -dc '0-9'` | `--output=pcent` 只出百分比；`tr -dc '0-9'` 去掉 `%` 和空格 |
| 内存百分比 | `free \| awk '/^Mem:/{printf "%.0f", $3/$2*100}'` | `$3`=used、`$2`=total |
| 负载百分比 | `awk -v l=$L1 -v c=$N 'BEGIN{printf "%.0f", l/c*100}'` | **`-v` 把 shell 变量传进 awk** |

## 五、生产实践

### 5.1 接入监控的三种方式

| 方式 | 做法 | 适合 |
|---|---|---|
| **cron + 退出码 + 通知** | `*/5 * * * * root /usr/local/bin/lab21-healthcheck.sh \|\| 发告警` | 最简单、无依赖 |
| **Prometheus textfile collector** | 脚本把指标写成 `node_exporter` 能读的 `.prom` 文件 | K8s/云原生环境 |
| Zabbix/Icinga 自定义检查 | 把脚本放到 `ExternalScripts` 目录，退出码决定告警级别 | 传统运维 |

**textfile 方式的写法：**

```bash
cat > /var/lib/node_exporter/textfile/health.prom <<EOF
health_disk_percent $DISK
health_memory_percent $MEM
health_load_percent $LOAD
health_critical_count $C
health_warning_count $W
EOF
```

**同时保留退出码**（cron 兜底）和**指标**（趋势图/告警规则）—— 两者不冲突。

### 5.2 阈值怎么定

| 指标 | 警告 | 严重 | 理由 |
|---|---|---|---|
| 磁盘 | **80%** | **90%** | 留出清理时间；到 95% 有些文件系统会保留给 root |
| 内存 | 85% | 95% | Linux 会尽量用满 cache，看 `available` 更准 |
| 负载 | **100%**（=核数） | **200%** | 满载到 2 倍排队，通常已影响响应 |

**阈值必须可配置**（本项用环境变量）：**数据库机和日志机的标准不该一样。**

### 5.3 告警要"可抑制、可分级、可收敛"

| 问题 | 做法 |
|---|---|
| 同一个问题每 5 分钟报一次 | 告警**去重/静默期**（同一 check 30 分钟内只报一次） |
| 半夜报磁盘 80% 吵醒人 | **WARN 走邮件/IM，CRIT 才电话** |
| 修好了没人知道 | **恢复通知**（状态从 CRIT → OK 也发一条） |
| 报了没人管 | 告警要绑定**值班人和处理时限**（否则就是噪音） |

### 5.4 巡检脚本该查什么（比"磁盘内存"更值钱的清单）

| 类别 | 检查项 |
|---|---|
| 资源 | 磁盘（含 inode `df -i`）、内存 available、load、文件句柄 `ulimit -n` |
| 服务 | 进程在不在、**端口在不在听**（`ss -tlnp`，比 `systemctl is-active` 更能反映"真能用"） |
| 业务 | 关键 URL 的 HTTP 状态码、关键 SQL 能否执行、证书剩余天数 |
| 数据 | 备份是否成功（最新备份时间）、主从延迟、连接数 |
| 安全 | 登录失败次数、sudo 使用、异常端口监听 |

**"服务 active" ≠ "服务可用"** —— 实验 17 讲过：容器 `Up` 但应用可能卡死。**要查"能不能真的提供服务"。**

### 5.5 脚本自身的健壮性

| 要求 | 做法 |
|---|---|
| 单点检查失败不能拖垮整体 | 每项用 `|| { echo "UNKNOWN"; }` 兜住 |
| 依赖命令缺失要能报 UNKNOWN | `command -v df >/dev/null || exit 3` |
| 超时保护 | `timeout 5 curl …`（实验 13 用过） |
| 输出别太长（否则告警里一堆字） | 只打异常项 + 一行汇总 |
| 日志 | `>> /var/log/health.log`，配 logrotate（实验 15） |

## 六、踩坑清单

| # | 坑 | 说明 / 正确做法 |
|---|---|---|
| 1 | 用 `set -e` 写巡检脚本 | **第一个检查失败就退出了**，后面的都不跑，退出码还可能是错的。巡检要 `set -uo pipefail`（**不要 `-e`**） |
| 2 | 用 `[ "$VAL" -ge 80 ]` 比较 load | **bash 只能比整数**，`0.35` 会报错。用 `awk "BEGIN{exit !(...)}"` |
| 3 | 先判 WARN 再判 CRIT | 95% 会先命中 85% 的 WARN 就返回了。**必须先判严重级别** |
| 4 | `systemctl is-active` 直接用 `$()` | 状态非 active 时它**既打印又返回非 0**，配合 `\|\|` 会出现双行（实验 17 的坑）。用 `\| head -1` |
| 5 | 阈值硬编码 | 不同机器不同标准。**用 `${DW:-80}` 环境变量** |
| 6 | 只看 `df` 不看 `df -i` | **inode 用满**时磁盘还有空间但**建不了新文件**（小文件多的场景常见） |
| 7 | 以为 `du` 变小就是空间释放了 | **`du` 会因为硬链接去重而"看起来变小"**（本项实测：`du -sh A B` 时 B 会跳过 A 已数的 inode）。**以 `df` 为准** |
| 8 | 以为删了文件 `df` 就该降 | 三种情况都不降：**被进程打开**（`lsof +L1`）、**被内核挂载**（`losetup -a`）、**还有硬链接**（`stat -c %h`） |
| 9 | 以为 `snap remove --revision` 能省空间 | **snapd 会把镜像搬进 `/var/lib/snapd/cache` 保回滚** → 删 `snaps/` 里的名字 ≠ 释放空间。**删 cache 也会被它重新填**（本项实测两次都失败） |
| 10 | **（本项我的错）** 判断 `/var/lib/snapd/cache` 全是硬链接 | 实际是 **snapd 主动把被删的镜像"搬"进去**了。**两次清理（删 cache、删桌面 snap）合计只回收约 100MB**，不是预期的 1.2G。**教训：清理前先确认"谁在持有这块空间"，不要假设** |
| 11 | 用 `sudo -n true` 验证"免密是否已撤销" | **`-n` 成功也可能是凭证时间戳还在**（默认 15 分钟）。**必须先 `sudo -k` 清缓存再测** |
| 12 | 脚本输出里带颜色，写进日志后满屏 `^[[31m` | 颜色只给终端；**重定向到文件时用 `--no-color` 或检测 `[ -t 1 ]`** |
| 13 | 巡检脚本跑得太频繁 | 磁盘/负载 1~5 分钟一次够；**每次都要读 `/proc`、`df`，太频繁有开销** |
| 14 | 只报"异常"不报"正常" | 告警链路需要"恢复通知"，所以**正常时也要能输出汇总**（本项一直打印 `WARN= C=` 那行） |

## 七、命令详解（本项首次出现）

### 7.1 取值

| 命令 / 参数 | 是什么 → 干什么 |
|---|---|
| **`df --output=pcent /`** | 只输出**使用百分比**列（含 `%`）；比 `df -h \| awk` 稳（列位置固定） |
| `tr -dc '0-9'` | `-d` 删除、`-c` 取反、`'0-9'` 保留数字 → **只留数字** |
| `free \| awk '/^Mem:/{...}'` | 取内存行；`$2`=total `$3`=used `$7`=available |
| `nproc` | CPU 核数（含超线程） |
| `/proc/loadavg` | 前三个数 = 1/5/15 分钟平均负载 |
| **`awk -v 变量=值 'BEGIN{...}'`** | **把 shell 变量传进 awk**（`-v` 是唯一可靠方式，别用字符串拼接） |
| `printf '%.0f'` | 浮点转整数（四舍五入） |

### 7.2 判断与输出

| 语法 | 说明 |
|---|---|
| **`$'\033[31m'`** | ANSI-C 引用，生成 ESC 序列 |
| `printf '%-6s' "$x"` | 左对齐、宽度 6 |
| **`awk "BEGIN{exit !($a >= $b)}"`** | **浮点比较**，结果通过退出码传给 bash |
| `[ "$x" = active ] && continue` | 短路写法（条件成立则跳过本轮） |
| `${var:-默认}` | 变量为空/未定义时用默认值 |

### 7.3 脚本控制

| 语法 | 说明 |
|---|---|
| **`set -uo pipefail`** | `-u` 未定义变量报错；`pipefail` 管道任一环失败算失败；**故意不加 `-e`** |
| `bash -n 文件` | **只做语法检查**，不执行 |
| `install -m 755 源 目标` | 复制 + 设权限（先写临时文件再 rename） |
| **`sudo -k`** | **清除 sudo 凭证时间戳** → 下次必须重新认证 |
| `sudo -n` | 非交互：需要密码就失败（**配合 `-k` 才有验证意义**） |

### 7.4 排查空间用到的

| 命令 | 用途 |
|---|---|
| `du -x -h --max-depth=1 /` | 各顶层目录占用（`-x` 不跨文件系统） |
| **`du -sh A B`（多个参数）** | ⚠️ **会对 A 已数的 inode 在 B 中跳过** → 看起来"B 变小了" |
| **`stat -c '%h %n' 文件`** | **`%h` = 硬链接数**（>1 说明还有别的名字） |
| **`lsof +L1`** | 链接数为 0 的**打开文件** = "删了但进程还占着" |
| **`losetup -a`** | loop 设备指向的文件 → "删了但内核还挂着" |
| `snap list --all` | 列出所有版本（含 `disabled` 旧版） |
| `snap remove 名字 --revision=N` | 删指定 revision（**N 是 rev 号，不是版本号**） |

| 验收项 | 结果 |

**面试可用的一句话总结：**

> 我写了个巡检脚本，检查磁盘/内存/负载/六个服务，超过阈值用 ANSI 标红，**退出码按 Nagios 惯例分 0/1/2**，并且阈值可以用环境变量覆盖，方便不同机器调。几个技术点：**bash 不能比小数，浮点比较用 `awk "BEGIN{exit !(...)}"` 代替**；**负载要除以核数换算成百分比**才能设统一阈值；**巡检脚本不能用 `set -e`**，因为要跑完所有检查再汇总退出码。另外我用 `> /dev/null` 验证了"退出码和输出无关"，这才是监控能用的前提。
