## 1. 任务目标与验收标准

**要做的三件事：**

1. 安装 `openssh-server`，能从 Windows 终端 SSH 连入虚拟机
2. 建一个普通用户，并赋予 `sudo` 权限
3. 关闭开机进入图形界面（`systemctl set-default multi-user.target`），需要时能切回

**验收标准：**

- 宿主机能 SSH 登录虚拟机
- 全程不用鼠标（纯键盘操作）
- `whoami` 的输出不是 `root`

**已知坑：** 先用 `ip a` 确认虚拟机 IP；NAT 模式下宿主机可直连该 IP。

## 2. 操作步骤

> 关键概念：**虚拟机控制台终端**（VMware 窗口里的黑框）和 **Windows Terminal 里的 SSH 会话**，是同一台机器上的两个 shell，命令效果完全一样。区别只在于后者走了 SSH 这条链路。任务要求"从 Windows 终端 SSH 连进去"，所以除装 ssh 那一步外，后续操作应尽量固定在 SSH 会话里做。

### 2.1 获取虚拟机 IP

在 VMware 控制台登录后执行：

```bash
ip a
```

在主网卡（`ens33` / `ens160` / `eth0`）下找 `inet` 那一行：

```
2: ens33: <BROADCAST,MULTICAST,UP,LOWER_UP> ...
    inet 192.168.9.128/24 brd 192.168.9.255 scope global dynamic ens33
         ^^^^^^^^^^^^^ 记这一段，不含 /24
```

**读法要点：**

- 只记 `inet` 后的地址本身，`/24` 是掩码不是地址的一部分
- 跳过 `127.0.0.1`（回环地址）
- 跳过 `virbr0`（`192.168.122.1`）、`docker0`（`172.17.0.1`）等虚拟网桥

**备选：从宿主机侧查（不必进图形界面）**

VMware NAT 的 DHCP 租约文件记录了分配情况：

```powershell
Get-Content C:\ProgramData\VMware\vmnetdhcp.leases | Select-String "lease|ip-address|hostname"
```

或直接用 `arp -a` 看邻居表。

### 2.2 宿主机确认网络可达

在 Windows Terminal / PowerShell 中：

```powershell
ping 192.168.9.128
```

期望 4 条回复、`TTL=64`、延迟 <1ms（同一台物理机内的虚拟网络）。

- 通 → 网络层没问题，继续
- 全超时 → 查 VMware 网络适配器是否为 **NAT 模式**、`编辑 → 虚拟网络编辑器` 中 vmnet8 是否存在
- `Destination host unreachable` → 宿主机 vmnet8 虚拟网卡被禁用或地址不对

### 2.3 安装 openssh-server

Ubuntu 24.04 默认**不预装** openssh-server。在虚拟机控制台执行（此时还没 SSH 通道，只能在这里敲）：

```bash
sudo apt update
sudo apt install -y openssh-server
```

**验证监听端口：**

```bash
sudo ss -tlnp | grep :22
```

本次实际输出：

```
LISTEN 0  4096  0.0.0.0:22  0.0.0.0:*  users:(("systemd",pid=1,fd=182))
LISTEN 0  4096     [::]:22     [::]:*  users:(("systemd",pid=1,fd=183))
```

> **怎么看**：出现 `0.0.0.0:22` 且处于 LISTEN 即为就绪。`users:(("systemd",pid=1,...))` 说明是 **socket 激活**（见术语表），属正常现象。
>
> **为什么不用 `systemctl status ssh` 判断**：socket 激活模式下无人连接时 `ssh.service` 显示 `inactive (dead)`，看着像没启动，其实是按需拉起。`ss` 看到的监听是最终事实。

**若 `ss` 里没有 :22：**

```bash
sudo systemctl enable --now ssh         # 若报 Unit not found 则改用下面这条
sudo systemctl enable --now ssh.socket
```

**若 UFW 防火墙开启，需放行：**

```bash
sudo ufw status
sudo ufw allow 22/tcp
```

### 2.4 从 Windows 终端 SSH 登录（验收点 1）

先确认用户名（在虚拟机里）：

```bash
whoami
```

然后在 Windows Terminal 中：

```powershell
ssh madrough@192.168.9.128
```

**首次连接会询问主机指纹：**

```
The authenticity of host '192.168.9.128 (192.168.9.128)' can't be established.
ED25519 key fingerprint is SHA256:xxxxxxxx.
Are you sure you want to continue connecting (yes/no/[fingerprint])?
```

必须输入完整单词 **`yes`**（不能只按回车，也不能只敲 `y`）。

**然后输入密码：** 密码输入时**屏幕无任何显示**（无星号、光标不动），盲打完直接回车。粘贴用**右键**或 `Ctrl+Shift+V`。

**成功标志：** 提示符变为 `用户名@主机名:~$`，例如 `madrough@ubuntulearn:~$`。

**配免密登录（可选，Windows 无 `ssh-copy-id`，用管道代替）：**

```powershell
ssh-keygen -t ed25519                                          # 已有密钥则跳过
type $env:USERPROFILE\.ssh\id_ed25519.pub | ssh madrough@192.168.9.128 "mkdir -p ~/.ssh && cat >> ~/.ssh/authorized_keys && chmod 700 ~/.ssh && chmod 600 ~/.ssh/authorized_keys"
```

之后 `ssh madrough@192.168.9.128` 即可直接进入。

### 2.5 创建普通用户并加入 sudo 组（验收点 2）

> **建议固定在这个 SSH 会话里操作**，不要退回 VMware 控制台。

**创建用户：**

```bash
sudo adduser madrough
```

交互提示：

```
New password:
Retype new password:
   （两次密码均不显示，盲打）
Full Name []:
Room Number []:
Work Phone []:
Home Phone []:
Other []:
Is the information correct? [Y/n]
```

- 密码两项**必填**（`adduser` 不接受空密码）
- 中间个人信息项**全部回车跳过**
- 最后一项直接回车（默认 Y）

成功后输出 `Adding new user 'madrough' ...`，并自动创建 `/home/madrough`、设置 bash shell、创建同名用户组。

> 与 `useradd` 的区别：`adduser` 是交互式封装，自动建家目录、设 shell、设密码；`useradd` 是底层命令，需手动加 `-m -s /bin/bash` 再 `passwd`。

**加入 sudo 组：**

```bash
sudo usermod -aG sudo madrough
```

> ⚠️ **`-aG` 的 `a` 绝对不能漏**。写成 `-G sudo` 会先把用户从所有附加组移除再加 sudo，是经典事故。

**验证组归属：**

```bash
id madrough
```

本次实际输出：

```
uid=1001(madrough) gid=1001(madrough) groups=1001(madrough),27(sudo),100(users)
```

`27(sudo)` 在列即达标。

**切换到该账号实测：**

```bash
su - madrough
```

- 要带 `-`（见术语表），否则不加载目标用户环境变量、不切到家目录
- 会要求输入 **madrough 的密码**

进去后提示符变为 `madrough@ubuntulearn:~$`，然后：

```bash
whoami
```

→ 必须输出 `madrough`

```bash
sudo whoami
```

→ 首次会要求输入 **madrough 自己的密码**，输出 `root` 即证明 sudo 生效

退出回原账号：

```bash
exit
```

> **关于 `su` 的选择**：
> - `su - madrough` → 切到 madrough 并加载其**登录环境**，推荐
> - `su madrough` → 切过去但保留原环境变量和当前目录
> - `su`（裸敲）→ 默认切 **root**；Ubuntu 默认未设 root 密码，会报 `Authentication failure`，**这是正常现象不是故障**
>
> **另一种验证方式（更干净）**：不开 `su`，直接在 Windows Terminal 另开一个窗口 `ssh madrough@192.168.9.128`，用 madrough 自己的身份登录，效果等价且更贴近真实使用场景。

### 2.6 关闭开机进入图形界面（验收点 3）

**改默认 target：**

```bash
sudo systemctl set-default multi-user.target
```

期望输出：

```
Removed /etc/systemd/system/default.target.
Created symlink /etc/systemd/system/default.target → /usr/lib/systemd/system/multi-user.target.
```

**验证：**

```bash
systemctl get-default
```

→ 必须输出 `multi-user.target`

**关于是否立即生效：**

`set-default` **只影响下一次开机**，当前运行环境不变。想立刻切换：

```bash
sudo systemctl isolate multi-user.target
```

- 会立刻杀掉图形会话，VMware 控制台变成黑底白字 tty 文本登录
- 通过 SSH 操作时**安全**（SSH 会话不受影响）
- 若正坐在 VMware 前面用图形界面操作，则会被踢到 tty

**日后切回图形界面：**

```bash
sudo systemctl set-default graphical.target   # 下次开机进图形
sudo systemctl isolate graphical.target       # 立即切回图形登录界面
```

注意 `isolate graphical.target` 只拉起显示管理器（GDM），**不会**自动替你登录。

### 2.7 重启与最终验收（全流程定论）

**重启：**

```bash
sudo reboot
```

SSH 会话立即断开，显示 `Connection to 192.168.9.128 closed by remote host.` —— **预期行为，不是错误**。

**等待 40~60 秒，然后全程在 PowerShell 里操作，不需要碰 VMware 窗口：**

```powershell
ping 192.168.9.128
```

通 → 直接连接。超时 → 多半是 DHCP 换了 IP，回 VMware 控制台 `ip a` 重新确认。

**重新登录（用新账号）：**

```powershell
ssh madrough@192.168.9.128
```

**进入后三条验收命令：**

```bash
whoami
```

本次实际输出：`madrough`

```bash
systemctl get-default
```

本次实际输出：`multi-user.target`

```bash
systemctl status gdm --no-pager
```

本次实际输出：`Unit gdm.service could not be found.`

> ⚠️ **这条输出不能单独作为图形界面已关闭的证据**：Ubuntu 24.04 的显示管理器服务名是 **`gdm3.service`**，查 `gdm.service` 本来就找不到。用下面这条权威确认：
>
> ```bash
> systemctl list-units --type=service --state=running | grep -Ei "gdm|lightdm|sddm|display-manager"
> ```
>
> **无任何输出** = 图形服务确实未运行。有输出则说明图形界面仍在跑。

**重启前后对照（可选）：**

```bash
uptime -s
```

显示几分钟前的启动时间，证明是重启后的新会话。

## 3. 术语解释（本次用到但容易含糊的概念）

### 3.1 `su` 系列

`su` = **s**ubstitute **u**ser（切换用户）。

| 命令 | 含义 | 备注 |
|---|---|---|
| `su` | 切到 **root** | Ubuntu 默认 root 无密码，会 `Authentication failure` |
| `su -` | 切到 root，加载 root 的登录环境 | 带 `-` 才像"真正登录" |
| `su madrough` | 切到 madrough，保留原环境变量和当前目录 | 环境可能污染 |
| `su - madrough` | 切到 madrough 并加载其登录环境 | **推荐用法** |
| `sudo -i` | 以 root 身份开一个交互式登录 shell | 等价于 `sudo su -` |
| `exit` | 退出当前 shell，回到上一层 | |

### 3.2 `sudo` 与 sudo 组

- `sudo cmd` = 以其他用户（默认 root）身份执行单条命令，验证的是**执行者自己的密码**
- Ubuntu 的 `/etc/sudoers` 默认含 `%sudo ALL=(ALL:ALL) ALL`，即**凡属 `sudo` 组的成员都获得完整 sudo 权限**
- 因此 `id` 输出里有 `27(sudo)` 就等同于"已具备 sudo 权限"
- 组变更后**需重新登录**才在会话中生效（`su - 用户` 或重开 SSH 均可）

### 3.3 systemd target

- target ≈ 启动"模式"（类似旧版 runlevel）
- `multi-user.target` ≈ 多用户命令行模式（旧 runlevel 3）
- `graphical.target` ≈ 图形界面模式（旧 runlevel 5）
- `/etc/systemd/system/default.target` 是指向某个 target 的软链接，**决定开机进入哪个模式**

| 命令 | 作用 |
|---|---|
| `systemctl get-default` | 查询当前默认 target |
| `systemctl set-default X` | 修改默认 target，**只影响下次开机** |
| `systemctl isolate X` | **立即**切换到 X（会停掉不相关的服务） |
| `systemctl list-units --type=service --state=running` | 列出正在运行的服务 |

### 3.4 socket 激活（socket activation）

- 传统方式：开机就把 sshd 进程常驻，一直占用 22 端口
- socket 激活：由 **systemd 先占住 22 端口**，等真有连接进来才临时拉起 sshd
- 特征：`ss -tlnp` 里 22 端口显示 `users:(("systemd",pid=1,...))` 而不是 `sshd`
- 影响：无人连接时 `systemctl status ssh` 显示 `inactive (dead)`，属正常
- 本次环境即为此模式

### 3.5 两个"终端"的区别

| | VMware 控制台终端 | Windows Terminal 里的 SSH 会话 |
|---|---|---|
| 本质 | 虚拟机显示器上的虚拟 tty | 经 TCP 22 端口连接的网络会话 |
| 断网/重启 | 仍然可用（本地） | 会断开 |
| 是否满足验收 | 不满足"从 Windows 终端 SSH 连进去" | **满足** |
| 使用建议 | 仅用于首次取 IP、装 ssh | 后续所有操作固定在此 |

## 4. 踩坑清单

| # | 坑 | 正确做法 |
|---|---|---|
| 1 | 服务名是 `ssh` 不是 `sshd` | `systemctl status ssh`；`sshd` 在 Ubuntu 上会 Unit not found |
| 2 | socket 激活下 `ssh.service` 显示 dead | 用 `ss -tlnp \| grep :22` 判断，不要只看 service 状态 |
| 3 | `usermod -G` 漏了 `-a` | 必须 `usermod -aG sudo 用户`，否则清空其他附加组 |
| 4 | `su 用户` 不带 `-` | 用 `su - 用户` 才加载完整登录环境 |
| 5 | Ubuntu 裸敲 `su` 失败 | root 无密码所致，正常；用 `sudo -i` 或 `su -` |
| 6 | `set-default` 误以为立即生效 | 只影响下次开机；要立即生效用 `isolate` |
| 7 | 以为 `isolate multi-user.target` 会断 SSH | 不会，只杀图形会话 |
| 8 | 查 `gdm.service` 查不到 | Ubuntu 24.04 服务名是 `gdm3.service`；或用 `list-units \| grep` 兜底 |
| 9 | SSH 首次连接不懂指纹提示 | 必须输入完整 `yes` |
| 10 | 密码输入时看不到字符以为卡住 | 正常，盲打完回车 |
| 11 | DHCP 导致 IP 变化后连不上 | 重启后先 `ping`，失败则回控制台 `ip a` 重查 |
| 12 | 组权限"没生效" | 退出重新登录（或 `su - 用户`）刷新会话组 |

## 5. 遗留隐患与后续建议

### 5.1 IP 是 DHCP 动态分配（建议优先处理）

`192.168.9.128` 由 VMware NAT 的 DHCP 分配，租约到期或重启后**可能变化**。后续任务若需反复连接，建议二选一：

**方案 A：在 Ubuntu 内配静态 IP（netplan，Ubuntu 24.04 适用）**

编辑 `/etc/netplan/` 下的 yaml（文件名因安装而异，常见 `50-cloud-init.yaml` 或 `01-network-manager-all.yaml`）：

```yaml
network:
  version: 2
  ethernets:
    ens33:
      dhcp4: false
      addresses: [192.168.9.128/24]
      routes:
        - to: default
          via: 192.168.9.2          # VMware NAT 网关，通常是网段 .2
      nameservers:
        addresses: [192.168.9.2, 8.8.8.8]
```

应用（注意缩进必须用空格，不能用 Tab）：

```bash
sudo netplan apply
```

**方案 B：在 VMware 里给 MAC 绑定固定租约**

`编辑 → 虚拟网络编辑器 → vmnet8 → DHCP 设置 → 添加`，把虚拟机 MAC（本次 `00:0c:29:bb:aa:db`）绑定到固定地址。优点是不动客户机配置。

### 5.2 其他可选加固

- **禁用密码登录改用密钥**：配好 2.4 的免密后，在 `/etc/ssh/sshd_config.d/` 下加文件写 `PasswordAuthentication no`，然后 `sudo systemctl restart ssh`
- **限制 sudo 需密码**：保持默认即可，不要配 `NOPASSWD`（学习环境够用且更安全）
- **记录 root 密码状态**：Ubuntu 默认 root 锁定，需 root shell 时用 `sudo -i`，不要 `sudo passwd root` 去解锁

## 7. 命令详解（本项首次出现的命令与参数）

> 原则：每个新出现的命令或参数，都要能说清「它是什么、这个参数干什么、为什么这里要用它」。

### 7.1 `ip a` — 看网络接口

```bash
ip a            # 简写，等价于 ip addr
ip -br a        # 单行简表，只看 IP 最省事
```

| 部分 | 含义 |
|---|---|
| `ip` | 新一代网络配置工具，取代老的 `ifconfig` / `route` |
| `a` | addr 的缩写，显示所有网络接口的地址 |
| `-br` | brief，每个接口压成一行 |

- **怎么读输出**：`2: ens33: <...> state UP` 是接口名和状态；`inet 192.168.9.128/24` 是 IPv4 地址；`inet6 fe80::...` 是 IPv6 链路本地地址（可以忽略）
- `/24` 是**掩码**不是地址的一部分
- 老命令 `ifconfig` 在新版 Ubuntu 上默认没装，装的是 `iproute2`

### 7.2 `getent` — 从系统数据库查用户/组

```bash
getent passwd                  # 相当于读 /etc/passwd，但包含 LDAP 等外部源
getent passwd madrough         # 只查一个用户
getent group                   # 查组
getent hosts 192.168.9.128     # 反查主机名
```

- **意义**：`cat /etc/passwd` 只看本地文件，`getent` 走 NSS（Name Service Switch），能把 LDAP/SSSD 等集中认证的用户也查出来。生产环境里**应该用 `getent` 而不是 `cat`**

### 7.3 `awk -F:` — 按分隔符取字段

```bash
getent passwd | awk -F: '$3 >= 1000 && $3 < 65534 {print $1, $3}'
```

拆开：

| 部分 | 含义 |
|---|---|
| `-F:` | field separator，按冒号切字段 |
| `$1` | 第 1 个字段（用户名） |
| `$3` | 第 3 个字段（UID） |
| `$4` | 第 4 个字段（GID / 组内成员） |
| `'条件 {动作}'` | 对满足条件的行执行动作 |
| `>= 1000 && < 65534` | 只留普通用户（1000 以下系统账号，65534 是 nobody） |

- `/etc/passwd` 七字段：`用户名:密码占位:UID:GID:描述:家目录:shell`
- `/etc/group` 四字段：`组名:密码占位:GID:成员列表`

### 7.4 `sudo` — 以其他用户身份执行单条命令

```bash
sudo systemctl status ssh        # 以 root 身份跑一条命令
sudo -i                          # 以 root 开一个交互式登录 shell
sudo -u alice whoami             # 以 alice 身份执行
sudo -l                          # 列出当前用户能 sudo 哪些命令
```

- **验证的是执行者自己的密码**，不是 root 的密码
- 权限来源：`/etc/sudoers` 里的 `%sudo ALL=(ALL:ALL) ALL`——凡属 `sudo` 组就有完整权限
- 组变更后**要重新登录**才生效
- `sudo` 默认记住密码 15 分钟（`timestamp_timeout`）

### 7.5 `apt` — 包管理

```bash
sudo apt update                 # 刷新软件源索引（不升级任何东西）
sudo apt install -y openssh-server
sudo apt remove openssh-server  # 卸载，保留配置
sudo apt purge openssh-server   # 卸载并删配置
sudo apt search openssh         # 搜包
```

| 命令 | 干什么 | 危险度 |
|---|---|---|
| `update` | 只更新"有哪些包、什么版本"的清单 | 无 |
| `upgrade` | 按清单升级已装的包 | 中 |
| `install` | 装包，**会自动装依赖** | 低 |
| `install -y` | 跳过确认提示 | 低 |

- `update` 和 `upgrade` 的区别是最常见的面试点：**update 只刷新索引，upgrade 才真正升级**

### 7.6 `ss -tlnp` — 查端口监听

```bash
sudo ss -tlnp | grep :22
```

| 参数 | 含义 |
|---|---|
| `-t` | TCP（`-u` 是 UDP） |
| `-l` | listening，只看监听状态 |
| `-n` | numeric，端口显示数字（`22`）而不是服务名（`ssh`） |
| `-p` | process，显示进程（**需要 root**） |

- **为什么不用 `systemctl status` 判断**：socket 激活模式下服务平时是 `inactive (dead)`，但端口照样在听。`ss` 是最终事实
- 老命令是 `netstat -tlnp`（`net-tools` 包，新版默认没装）

### 7.7 `systemctl` 基本用法

```bash
sudo systemctl enable --now ssh        # 设开机自启 + 立刻启动
sudo systemctl status ssh.socket --no-pager
sudo systemctl disable ssh
sudo systemctl restart ssh
```

| 参数 | 含义 |
|---|---|
| `enable` | 设开机自启（创建软链） |
| `--now` | 同时立刻启动，等价于 `enable` + `start` |
| `disable` | 取消开机自启（不停止正在跑的） |
| `restart` | 重启服务 |
| `--no-pager` | 不要用 `less` 分页 |

### 7.8 `systemctl set-default` / `isolate` / `get-default`

```bash
systemctl get-default                      # 查当前默认 target
sudo systemctl set-default multi-user.target   # 改默认（只影响下次开机）
sudo systemctl isolate multi-user.target       # 立即切换
```

| 命令 | 作用范围 |
|---|---|
| `set-default` | **只管下次开机**，当前不动 |
| `isolate` | **立即**切，会停掉不相关的服务 |
| `get-default` | 读 `/etc/systemd/system/default.target` 软链 |

- target ≈ 旧的 runlevel：`multi-user` ≈ 3（命令行），`graphical` ≈ 5（图形）

### 7.9 `whoami` / `id` / `uptime`

```bash
whoami          # 当前用户名（受 su/sudo 影响）
id              # uid、gid、所有附加组
id alice        # 查别人
uptime          # 开机多久、负载
uptime -s       # 开机时间点
who -b          # 上次启动时间
```

- `whoami` 和 `logname` 的区别：`whoami` 看**当前有效身份**，`logname` 看**最初登录的账号**。`sudo -i` 后 `whoami` 是 root，`logname` 还是你

### 7.10 `su` 家族

```bash
su                 # 切 root（Ubuntu 会失败，root 无密码）
su -               # 切 root 并加载登录环境
su - alice         # 切 alice，加载其登录环境（推荐）
su alice           # 切 alice，保留原环境变量与当前目录
exit               # 退回上一层
```

- **带 `-` 的区别**：`su -` 相当于"以该用户重新登录"，会重置环境变量、切到家目录、执行其 profile
- `sudo -i` ≈ `sudo su -`，都是以 root 开登录 shell

### 7.11 `usermod -aG` — 给已有用户追加组

```bash
sudo usermod -aG sudo madrough
```

| 部分 | 含义 |
|---|---|
| `-a` | **append**，追加而不是替换 |
| `-G` | 指定附加组列表 |
| 不加 `-a` 的 `-G` | **把用户从所有其他附加组里踢出去**（经典事故） |

- 改完**必须重新登录**（或 `su - 用户`）才在会话里生效

### 7.12 `adduser` vs `useradd`

```bash
sudo adduser madrough                          # 交互式，全自动
sudo useradd -m -s /bin/bash -G devs alice     # 底层，需自己指定
```

| | `adduser` | `useradd` |
|---|---|---|
| 类型 | Debian/Ubuntu 的封装脚本 | 底层命令（各发行版通用） |
| 家目录 | 自动建 | 要加 `-m` |
| shell | 自动设 bash | 要加 `-s` |
| 密码 | 交互式设置 | 不设（需 `passwd` 或 `chpasswd`） |
| 同名组 | 自动建 | 取决于 `USERGROUPS_ENAB` |

### 7.13 `ssh` 客户端

```bash
ssh madrough@192.168.9.128
ssh -p 2222 user@host          # 指定端口
ssh -i ~/.ssh/id_ed25519 user@host   # 指定私钥
ssh -v user@host               # 调试模式（连不上时用）
```

- 首次连接要确认主机指纹（输完整 `yes`）
- `-v` 会打印详细握手过程，**排查"Connection refused / timeout"必用**

### 7.14 `ssh-keygen` / 免密登录

```bash
ssh-keygen -t ed25519          # 生成密钥对，-t 指定算法
```

| 参数 | 含义 |
|---|---|
| `-t ed25519` | 密钥类型，比 RSA 更短更安全，现代首选 |
| `-b 4096` | 位数（RSA 才用） |
| `-f 路径` | 指定输出文件名 |

- 生成 `~/.ssh/id_ed25519`（私钥，**绝不外传**）和 `id_ed25519.pub`（公钥）
- Windows 没有 `ssh-copy-id`，用 `type 公钥 | ssh ... "cat >> ~/.ssh/authorized_keys"` 代替

### 7.15 `grep -Ei`

```bash
grep -Ei "gdm|lightdm|sddm|display-manager"
```

| 参数 | 含义 |
|---|---|
| `-E` | 扩展正则，支持 `\|` 表示"或" |
| `-i` | 忽略大小写 |

- 等价写法：`grep -i -e gdm -e lightdm`（多个 `-e` 代替正则或）
- **`|` 是 shell 的管道符**，在正则里要用引号包起来，否则被 shell 抢先解释

### 7.16 `ping`

```powershell
ping 192.168.9.128
```

- Windows 默认发 4 个包就停；Linux 默认**一直发**，要 `Ctrl+C` 中断或 `-c 4`
- `TTL=64` 说明对端是 Linux 且没经过路由器
- **能被 ping 通 ≠ 服务可用**。ping 走 ICMP，`sshd` 走 TCP 22，是两回事
