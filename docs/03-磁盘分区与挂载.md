# 03 磁盘分区与挂载

> 实验日期：2026-10-28
> 环境：Ubuntu 24.04.5 LTS（`ubuntulearn` / `192.168.9.128`），VMware Workstation
> 快照：`lab-03-开始`
> ⚠️ 本项做实验时**真的把系统搞到起不来过一次**，完整事故复盘见第七节。这次事故是本项最有价值的部分。

## 一、目标与验收

**做：** VMware 里加一块 2G 虚拟盘 → 分区 → 格式化成 ext4 → 挂载到 `/data` → 写进 `/etc/fstab` → 重启验证还在

**验收：**

- 重启后 `df -h` 里仍有 `/data`
- **故意写错 fstab，能自己救回来**

## 二、本机磁盘环境（动手前必须摸清）

```
lsblk
sda                         8:0    0    20G  0 disk
├─sda1                      8:1    0     1M  0 part          ← BIOS boot 分区
├─sda2                      8:2    0   1.8G  0 part /boot
└─sda3                      8:3    0  18.2G  0 part
  └─ubuntu--vg-ubuntu--lv 252:0    0    10G  0 lvm  /        ← LVM 逻辑卷
```

**三个必须注意的特点：**

1. **根分区在 LVM 上**（`/dev/mapper/ubuntu--vg-ubuntu--lv`），不是普通分区。`df -h` 里 `/` 显示的是逻辑卷，不是 `sda3`
2. **Legacy BIOS 启动**：`sda1` 只有 1M 且不挂载，是 BIOS boot 分区（不是 EFI 分区），所以 fstab 里没有 `/boot/efi`
3. 只有 `sda` 一块盘，新加的盘会是 `sdb`

## 三、操作步骤

> 约定：每个命令块标注执行身份。

### 3.1 在 VMware 里加 2G 磁盘（热添加，不用关机）

**虚拟机 → 设置 → 添加 → 硬盘 → SCSI → 创建新虚拟磁盘 → 2 GB（不勾"立即分配"）→ 存储为单个文件 → 完成**

热添加的盘 Linux 不一定马上识别，主动触发扫描：

```bash
# 身份：madrough
madrough@ubuntulearn:~$ for h in /sys/class/scsi_host/host*/scan; do echo "- - -" | sudo tee $h; done
madrough@ubuntulearn:~$ lsblk
```

期望出现：

```
sdb                         8:16   0     2G  0 disk
```

**只有 `sdb` 一行、下面没有子项** = 裸盘，正是要的状态。

```bash
# 身份：madrough
madrough@ubuntulearn:~$ sudo fdisk -l /dev/sdb
# Disk /dev/sdb: 2 GiB, 2147483648 bytes, 4194304 sectors
```

### 3.2 分区

```bash
# 身份：madrough
madrough@ubuntulearn:~$ sudo fdisk /dev/sdb
```

交互内依次敲：**`n` → `p` → `1` → 回车（起始扇区默认）→ 回车（结束扇区默认）→ `w`**

| 按键 | 含义 |
|---|---|
| `n` | 新建分区 |
| `p` | 主分区 |
| `1` | 分区号 |
| 两次回车 | 起始/结束扇区全用默认 = 占满整盘 |
| `w` | **写入并退出**（敲 `q` 则全部作废） |

验证：

```bash
sdb                         8:16   0     2G  0 disk
└─sdb1                      8:17   0     2G  0 part
```

```bash
# Device     Boot Start     End Sectors Size Id Type
# /dev/sdb1        2048 4194303 4192256   2G 83 Linux
```

`Start 2048` = 1MiB 对齐，对 4K 扇区性能有利。

### 3.3 格式化为 ext4

```bash
# 身份：madrough
madrough@ubuntulearn:~$ lsblk | grep -A1 sdb        # 再次确认是 sdb1，别手滑
madrough@ubuntulearn:~$ sudo mkfs.ext4 /dev/sdb1
```

输出里记下 **`Filesystem UUID`**，本机是：

```
565fb750-a5c6-431a-98e7-4d941943f73a
```

验证：

```bash
# 身份：madrough
madrough@ubuntulearn:~$ sudo blkid /dev/sdb1
# /dev/sdb1: UUID="565fb750-..." BLOCK_SIZE="4096" TYPE="ext4" PARTUUID="cd3c9c22-01"
```

**`mkfs` 到底做了什么**：不是"清空数据"，而是往分区写一套文件系统结构（超级块、inode 表、块位图）。没有文件系统的分区，内核不知道怎么在上面存文件。

### 3.4 挂载

```bash
# 身份：madrough
madrough@ubuntulearn:~$ sudo mkdir -p /data
madrough@ubuntulearn:~$ sudo mount UUID=565fb750-a5c6-431a-98e7-4d941943f73a /data
madrough@ubuntulearn:~$ df -h /data
# /dev/sdb1  2.0G  24K  1.9G  1%  /data
madrough@ubuntulearn:~$ findmnt /data
# /data /dev/sdb1 ext4 rw,relatime
```

写测试文件：

```bash
# 身份：madrough
madrough@ubuntulearn:~$ sudo bash -c 'echo "hello from sdb1" > /data/hello.txt'
madrough@ubuntulearn:~$ cat /data/hello.txt
```

> `sudo echo ... > /data/x` 不行——重定向是当前 shell 干的，不是 sudo。要用 `sudo tee` 或 `sudo bash -c`。

**此时挂载是临时的**：`mount` 只在内存生效，重启就没了。这就是要 fstab 的原因。

### 3.5 写进 /etc/fstab

```bash
# 身份：madrough
madrough@ubuntulearn:~$ sudo cp /etc/fstab /etc/fstab.bak
madrough@ubuntulearn:~$ echo "UUID=565fb750-a5c6-431a-98e7-4d941943f73a /data ext4 defaults 0 2" | sudo tee -a /etc/fstab
madrough@ubuntulearn:~$ tail -3 /etc/fstab
```

**`sudo echo "..." >> /etc/fstab` 是经典陷阱**：`>>` 由当前 shell 执行，不是 sudo 执行，照样 permission denied。必须用 `sudo tee -a`。

**fstab 六个字段：**

| 字段 | 值 | 含义 |
|---|---|---|
| ① 设备 | `UUID=565fb750-...` | 挂什么 |
| ② 挂载点 | `/data` | 挂到哪 |
| ③ 类型 | `ext4` | 文件系统类型 |
| ④ 选项 | `defaults` | rw/suid/exec/auto/nouser/async 的集合 |
| ⑤ dump | `0` | 给 dump 工具用，已弃用，填 0 |
| ⑥ fsck 顺序 | `2` | 根为 1，其他为 2，0 = 不自检 |

### 3.6 不重启就验证（关键习惯）

```bash
# 身份：madrough
madrough@ubuntulearn:~$ sudo umount /data
madrough@ubuntulearn:~$ sudo systemctl daemon-reload
madrough@ubuntulearn:~$ sudo mount -a
madrough@ubuntulearn:~$ df -h /data
```

`mount -a` = 按 fstab 挂载所有未挂载的条目。**这一步过了再重启**，否则就是把错误带进重启。

### 3.7 重启验证

```bash
# 身份：madrough
madrough@ubuntulearn:~$ sudo reboot
```

重启后：

```bash
# 身份：madrough
madrough@ubuntulearn:~$ df -h /data
madrough@ubuntulearn:~$ cat /data/hello.txt
madrough@ubuntulearn:~$ systemctl --failed
```

`hello.txt` 还在 → 数据在盘上、挂载成功、不丢。`--failed` 干净 → 无失败单元。

### 3.8 加 nofail 保险（本项最重要的加固）

```bash
# 身份：madrough
madrough@ubuntulearn:~$ sudo cp /etc/fstab /etc/fstab.withdata
madrough@ubuntulearn:~$ sudo sed -i 's|/data ext4 defaults 0 2|/data ext4 defaults,nofail,x-systemd.device-timeout=5s 0 2|' /etc/fstab
madrough@ubuntulearn:~$ tail -2 /etc/fstab
# UUID=565fb750-... /data ext4 defaults,nofail,x-systemd.device-timeout=5s 0 2
madrough@ubuntulearn:~$ sudo systemctl daemon-reload
madrough@ubuntulearn:~$ sudo mount -a
madrough@ubuntulearn:~$ df -h /data
```

| 选项 | 作用 |
|---|---|
| `nofail` | 挂载失败**不再阻断启动**，系统继续走，只是 `data.mount` 标记 failed |
| `x-systemd.device-timeout=5s` | 设备不存在时**只等 5 秒**就放弃，而非默认 90 秒；必须配合 `nofail` |
| `x-systemd.` 前缀 | 给 systemd 的参数，`mount` 命令不认（会忽略），不影响手工挂载 |

## 四、fstab 与 systemd 的关系

- 开机时 `systemd-fstab-generator` 把 `/etc/fstab` 的每一行**编译成一个 `.mount` 单元**（如 `data.mount`）
- 没有 `nofail` 的条目会被挂到 **`local-fs.target`** 上，且是 **`Requires`（强依赖）**

> ### ⚠️ 更正（2026-11-11，实验 15 实测）
>
> 本节原来写的是"**任何一行挂载失败 → `local-fs.target` 失败 → 进 emergency mode**"。**这个说法不准确**，实验 15 用两种故障形态做了对照：
>
> | 故障形态 | `data.mount` 的状态 | 结果 |
> |---|---|---|
> | **设备等不到**（UUID 不存在，等满 `x-systemd.device-timeout` 超时） | **`inactive (dead)`** —— mount job 被**取消（cancelled）**，不是失败 | **降级启动，不进 emergency**；`systemctl --failed` 还是 `0 loaded units`，但 `/data` **静默消失** |
> | **设备在但挂载失败**（如把 `ext4` 写成 `xfs`） | **`failed`** | **`local-fs.target` 失败 → 进 emergency mode** |
>
> **准确表述：不是"挂载失败"就进 emergency，而是"`mount` 单元进入 `failed` 状态"才进。** 设备超时的情形下单元是 `inactive (dead)`，不会拖垮启动链 —— **系统看起来一切正常，只有那块盘悄悄不在了**（这比 emergency 更危险，因为 `--failed` 是干净的）。
>
> 详细实测见 [15 故障演练](15-故障演练.md) 第二节。

**在运行中的系统改了 fstab，正确顺序永远是：**

```
改 fstab → systemctl daemon-reload → mount -a 验证
```

少了 `daemon-reload`，systemd 还按老配置干活，`mount -a` 会报：

```
mount: your fstab has been modified, but systemd still uses the old version;
       use 'systemctl daemon-reload' to reload
```

这是**警告不是错误**，但必须照做。`daemon-reload` 只重读配置，**不挂载也不卸载**，所以后面还要跟 `mount -a`。

## 五、为什么用 UUID 不用 /dev/sdb1

设备名会变：加盘、换接口、改 SCSI 顺序后 `sdb` 可能变成 `sdc`，fstab 就指向错误的盘，甚至把别的盘挂到 `/` 上。UUID 是文件系统自己的身份证，只要不重新 `mkfs` 就不变。

```bash
sudo blkid                     # 看所有设备的 UUID
ls -l /dev/disk/by-uuid/       # UUID → 设备名的软链接
```

fstab 里也可以用 `/dev/disk/by-uuid/xxx` 这种路径写法，效果同上（`/boot` 那行就是这样）。

## 六、救援手段（这次用到了第一种）

### 6.1 emergency mode 的控制台 root shell

系统起不来时会掉进 emergency mode。Ubuntu 默认 **root 账号锁定（无密码）**，所以会看到：

```
You are in emergency mode. ...
Cannot open access to console, the root account is locked.
Press Enter to continue.
```

**按 `Enter`** 可以继续启动（忽略失败），有机会进入多用户状态。本次就是这样拿到 root shell 的。

### 6.2 从控制台切虚拟终端

VMware 里 `Ctrl+Alt+<F1..F6>` 会被宿主机截获。正确姿势：

**先按 `Ctrl+Alt+Space`（松开），再按 `F1` / `F2`**

本次就是在 tty2 上看到登录界面，才发现系统其实已经启动完成。

### 6.3 GRUB 里屏蔽某个挂载单元（本次备用方案）

重启时按 `↑`/`↓` 打断自动启动 → 按 `e` → 在 `linux ...` 行尾加：

```
systemd.mask=data.mount
```

→ `Ctrl+X` 启动。systemd 会完全跳过该挂载，不管盘在不在、fstab 对不对都能起来。

### 6.4 GRUB 里直接进 root shell（最硬的一招）

在 `linux ...` 行尾加：

```
rw init=/bin/bash
```

→ `Ctrl+X`。直接进 bash（以 root 身份、不启动 systemd），然后：

```bash
mount -o remount,rw /
# 改 fstab
exec /sbin/init
```

### 6.5 只读文件系统

emergency mode 下 `/` 默认**只读**，改配置前必须先：

```bash
mount -o remount,rw /
```

否则 `cp`/`nano` 会报 `Read-only file system`。

## 七、事故复盘（本次真的把系统搞挂了）

这是本项最值钱的部分。目标：验证"故意写错 fstab 能否救回来"。

### 7.1 时间线

| 步骤 | 操作 | 结果 |
|---|---|---|
| 1 | `sudo cp /etc/fstab /etc/fstab.good` | 存好配置 |
| 2 | `sudo sed -i 's/565fb750/565fb7500/' /etc/fstab` | UUID 多了一个 `0` |
| 3 | `sudo umount /data && sudo mount -a` | 报 `mount: /data: can't find UUID=565fb7500-...` |
| 4 | `sudo reboot` | **开机掉进 emergency mode** |
| 5 | 控制台按 `Enter` | 拿到 root shell（`root@ubuntulearn:~#`） |
| 6 | `mount -o remount,rw /` | 把 `/` 改成可写 |
| 7 | `cp /etc/fstab.good /etc/fstab` | 恢复正确配置 |
| 8 | `mount -a` | 报 warning：fstab 改了但 systemd 还用旧的 |
| 9 | `systemctl daemon-reload` 后再 `mount -a` | `/data` 挂载成功 |
| 10 | `reboot` | 一度卡在 `System is booting up`，登录被拒 |
| 11 | 强制重启虚拟机 | 正常启动，一切恢复 |

### 7.2 关键教训

1. **没有 `nofail` 的 fstab 条目失败 = 系统起不来。** 我事先预判"只破坏 `/data` 不会影响启动"是**错的**——`local-fs.target` 是强依赖，任何一条挂载失败都会把整个启动链拖垮
2. **改正后必须 `daemon-reload`**，否则 systemd 按老配置干活，会看到"配置明明改对了却不生效"
3. **`systemctl --failed` 为 0 不等于没故障**——如果单元根本没被启动，状态是 `inactive (dead)` 而不是 `failed`，容易被误读
4. **控制台黑屏 ≠ 系统挂了**。本次 tty1 无输出、tty2 却是登录界面，切换 VT 才看清真相
5. **`System is booting up` 是 PAM 的 `/run/nologin`**，说明有启动任务没完成（多半在等 90 秒超时）
6. **`ping` 通 + SSH `Connection refused`** = 内核和网络起来了，但 22 端口没进程监听。第一件事查 `sudo ss -tlnp | grep :22`，不要急着怀疑 fstab

### 7.3 nofail 的对照实验（收尾验证）

修好并加上 `nofail` 后，**用同样的坏 UUID 再演一次**：

```bash
# 身份：madrough
madrough@ubuntulearn:~$ sudo sed -i 's/565fb750/565fb7500/' /etc/fstab
madrough@ubuntulearn:~$ sudo systemctl daemon-reload
madrough@ubuntulearn:~$ sudo reboot
```

**结果与 7.1 第 4 步完全不同：**

| | 没有 `nofail` | 有 `nofail` |
|---|---|---|
| 开机 | 掉进 emergency mode，起不来 | **正常到登录界面** |
| SSH | 不通（或部分服务未起） | **直接能连** |
| `systemctl --failed` | 整个启动链失败 | 只有 `data.mount failed` |
| `df -h` | 无 `/data` | 无 `/data` |
| 恢复方式 | 得进控制台救援 | 改回 fstab 即可，系统一直可用 |

验证完用 `/etc/fstab.withdata` 恢复。

## 八、踩坑清单

| # | 坑 | 正确做法 |
|---|---|---|
| 1 | `sudo echo "..." >> /etc/fstab` 提权失败 | 重定向由当前 shell 执行，用 `sudo tee -a` |
| 2 | 以为只有破坏 `/` 才会导致起不来 | 没有 `nofail` 的任何 fstab 条目失败都会进 emergency mode |
| 3 | 改了 fstab 直接 `mount -a`，看到"systemd still uses the old version" | 先 `systemctl daemon-reload`，再 `mount -a` |
| 4 | 在 emergency mode 里直接 `cp` 改 fstab，报只读文件系统 | 先 `mount -o remount,rw /` |
| 5 | Ubuntu emergency mode 要求 root 密码但 root 被锁定 | 按 `Enter` 继续启动，或走 GRUB（`systemd.mask=` / `init=/bin/bash`） |
| 6 | 在 VMware 里按 `Ctrl+Alt+F1` 没反应 | 先 `Ctrl+Alt+Space` 再按 F1 |
| 7 | 控制台黑屏就以为系统挂死 | 切换 VT（F1/F2）确认，`ping` 从外部交叉验证 |
| 8 | `systemctl --failed` 为 0 就认为没故障 | 未启动的单元是 `inactive (dead)`，不是 `failed` |
| 9 | `ping` 通但 SSH 拒绝，去查 fstab | 先查 `ss -tlnp \| grep :22`，看 sshd 有没有起来 |
| 10 | 热添加磁盘后 `lsblk` 看不到 | 扫描 SCSI 总线，或干脆关机加盘再开机 |
| 11 | 把 `sdb1` 写成 `sda1`（`mkfs` 会毁系统） | 执行 `mkfs` 前 `lsblk | grep` 再确认一次 |
| 12 | 忘了 `nofail` | 非关键挂载一律 `defaults,nofail,x-systemd.device-timeout=5s` |

## 十、命令速查

```bash
# 加盘后识别
for h in /sys/class/scsi_host/host*/scan; do echo "- - -" | sudo tee $h; done
lsblk

# 分区（交互：n → p → 1 → 回车 → 回车 → w）
sudo fdisk /dev/sdb
sudo fdisk -l /dev/sdb

# 格式化并取 UUID
sudo mkfs.ext4 /dev/sdb1
sudo blkid /dev/sdb1

# 临时挂载
sudo mkdir -p /data
sudo mount UUID=xxx /data
findmnt /data
df -h /data

# 持久化（改完必须 daemon-reload）
sudo cp /etc/fstab /etc/fstab.bak
echo "UUID=xxx /data ext4 defaults,nofail,x-systemd.device-timeout=5s 0 2" | sudo tee -a /etc/fstab
sudo systemctl daemon-reload
sudo mount -a

# 排查
systemctl --failed
sudo journalctl -xb --no-pager | tail -50
sudo journalctl -b -u data.mount -n 30 --no-pager
sudo ss -tlnp | grep :22

# 救援
mount -o remount,rw /
cp /etc/fstab.bak /etc/fstab
systemctl daemon-reload && mount -a
```

## 十一、遗留 / 注意事项

- 磁盘 20G，根分区 9.8G 已用 71%（**剩 2.8G，后续装 MySQL / Docker / Prometheus 会不够**）。实验 12 之前建议先扩容 LVM 逻辑卷（`lvextend` + `resize2fs`），或再加一块盘
- `sdb` 是**热添加**的。如果后续出现"重启后盘不见了"，回 VMware 设置确认硬盘条目是否持久保存；必要时关机加盘
- `/etc/fstab.bak`、`/etc/fstab.good`、`/etc/fstab.withdata` 三个备份文件留着，后面故障演练还用得上

## 十二、命令详解（本项首次出现的命令与参数）

> 原则：**每个新出现的命令或参数，都要能说清「它是什么、这个参数干什么、为什么这里要用它」**。按本项出现顺序排列。

### 12.1 `lsblk` — 列出块设备

```bash
lsblk            # 树状列出所有块设备及挂载点
lsblk -f         # 额外显示文件系统类型、UUID、卷标
lsblk | grep -A1 sdb   # 只看 sdb 及其后面 1 行（即 sdb1）
```

- **意义**：比 `fdisk -l` 更友好，能一眼看出"磁盘 → 分区 → 挂载点"的层级
- `-f` = filesystem，显示 FSTYPE / UUID / LABEL / 使用率
- `-A1` 里的 `A` 是 grep 的 after，见 12.9

### 12.2 `fdisk` — 分区工具

```bash
sudo fdisk -l /dev/sdb     # 只读式列出该盘的分区表
sudo fdisk /dev/sdb        # 进入交互式分区界面
```

- `-l` = list，**只列不改**，安全
- 不带 `-l` 进入交互后，是**子命令模式**，按键含义：

| 键 | 作用 |
|---|---|
| `n` | new，新建分区 |
| `p` | primary，主分区（对比 `e` 扩展分区） |
| `1` | 分区编号 |
| 回车 | 用默认扇区（起始 2048 = 1MiB 对齐） |
| `w` | **write**，写入分区表并退出（真正生效） |
| `q` | **quit**，放弃所有改动退出 |
| `m` | 帮助菜单 |
| `p` | （在分区已建后）打印当前分区表 |

> `n` 和 `p` 都用了字母 `p`，注意上下文：`n` 之后问类型时 `p` = 主分区；回到主菜单后 `p` = print。

### 12.3 `mkfs.ext4` — 创建 ext4 文件系统

```bash
sudo mkfs.ext4 /dev/sdb1
sudo mkfs.ext4 -L data /dev/sdb1    # 顺带设卷标，可选
```

- **意义**：`mkfs` = make filesystem。分区只是"划好地"，`mkfs` 才是"铺好地板"——写入超级块、inode 表、块位图
- **危险**：会**抹掉目标分区上的所有数据**。执行前务必 `lsblk` 确认设备名
- 类似命令：`mkfs.xfs`、`mkfs.vfat`、`mkswap`

### 12.4 `blkid` — 查看块的 UUID 与类型

```bash
sudo blkid              # 列出所有设备的 UUID/TYPE
sudo blkid /dev/sdb1    # 只看一个
```

- **意义**：fstab 里要写 `UUID=...` 时，UUID 就从这里取
- 输出字段：`UUID`（文件系统身份）、`TYPE`（文件系统类型）、`PARTUUID`（分区表里的 ID，和 UUID 不是一回事）

**`UUID` 和 `PARTUUID` 的区别**（容易混）：UUID 属于**文件系统**，重新 `mkfs` 会变；PARTUUID 属于**分区表**，只跟分区有关，格式化不影响。

### 12.5 `mount` / `umount` — 挂载与卸载

```bash
sudo mount UUID=xxx /data      # 按 UUID 挂载到 /data
sudo mount -a                  # 挂载 fstab 里所有尚未挂载的条目
sudo mount -o remount,rw /     # 把已挂载的 / 改成可写（不改挂载点）
sudo mount /data               # 只挂 fstab 里与 /data 对应那条
sudo umount /data              # 卸载（注意是 umount，少个 n）
```

| 参数 | 含义 |
|---|---|
| `-a` | all，按 `/etc/fstab` 全部挂一遍；已在挂的会跳过 |
| `-o` | options，逗号分隔的挂载选项，如 `remount,rw`、`defaults`、`nofail` |
| `-t` | type，指定文件系统类型（通常可省略，内核会探测） |

- **`remount` 的作用**：不卸载直接改挂载选项。emergency mode 下 `/` 是只读的，必须靠它改成可写才能改配置
- **`umount` 报 `target is busy`**：有进程在用这个目录，`lsof /data` 或 `fuser -m /data` 找出占用者

### 12.6 `findmnt` — 查挂载状态（比 `mount` 干净）

```bash
findmnt /data
# TARGET SOURCE    FSTYPE OPTIONS
# /data  /dev/sdb1 ext4   rw,relatime
```

- **意义**：专门查"某个挂载点到底挂的是什么"，输出是干净表格
- 直接敲 `findmnt` 会以树状列出全部挂载，比 `mount` 命令好读

### 12.7 `df -h` — 磁盘使用率

```bash
df -h            # 人类可读（G/M 单位）
df -h /data      # 只看某个挂载点
df -h | grep sdb # 按设备过滤
```

- `-h` = human-readable，把字节换算成 K/M/G
- `df` 看的是**文件系统层面**的剩余空间；`du` 看的是**目录占用**，两者经常对不上（被删除但被进程占用的文件也算在 df 里）

### 12.8 `tee` — 一边输出一边写文件（配合 sudo）

```bash
echo "内容" | sudo tee -a /etc/fstab
```

| 参数 | 含义 |
|---|---|
| `-a` | append，追加；不加则覆盖 |
| `-i` | 忽略中断信号（较少用） |

- **为什么需要它**：`sudo echo "x" >> /etc/fstab` **不生效**。因为重定向 `>>` 是**当前 shell**（普通用户）执行的开文件动作，sudo 只提升了 `echo` 的权限，开文件仍被拒
- `tee` 是真正以 sudo 身份打开文件并写入的程序，所以能绕过这个限制

### 12.9 `grep` 的常用选项

```bash
grep sdb            # 包含 sdb 的行
grep -A1 sdb        # 命中行 + 后面 1 行（after）
grep -B1 sdb        # 命中行 + 前面 1 行（before）
grep -C1 sdb        # 前后各 1 行（context）
grep -E "a|b"       # 扩展正则，支持 | 或
grep -i             # 忽略大小写
grep -v             # 反向：不包含的行
```

- **`|` 在正则里是"或"**，但在 shell 里是管道，所以**必须加引号**：`grep -E "gdm|sddm"`

### 12.10 `sed -i` — 流编辑器原地改文件

```bash
sed -i 's/565fb750/565fb7500/' /etc/fstab
sed -i 's|/data ext4 defaults 0 2|/data ext4 defaults,nofail 0 2|' /etc/fstab
```

| 部分 | 含义 |
|---|---|
| `-i` | in-place，直接改文件（不加则只输出到屏幕） |
| `s/a/b/` | substitute，把 a 换成 b |
| `s/a/b/g` | 末尾 `g` = 全部替换，不加则每行只换第一处 |
| `|` 作分隔符 | 内容里含 `/` 时换个别的不冲突的分隔符（`|`、`#`、`,` 都行） |

- **坑**：`sed -i` 改错了没提示，所以改之前 `cp` 备份；改完 `tail`/`diff` 确认
- `sed` 默认逐行处理，不理解结构，用它改配置文件属于"能用但脆"的手段，重要文件建议 `nano` 手改

### 12.11 `tail` / `head` — 看文件头尾

```bash
tail -3 /etc/fstab        # 最后 3 行（= tail -n 3）
tail -n 3 /etc/fstab      # 推荐写法
tail -f /var/log/syslog   # 跟随追加（follow），Ctrl+C 退出
head -5 /etc/fstab        # 前 5 行
```

- **`-2`、`-3` 这种写法是省略了 `-n`**：数字紧跟在 `-` 后表示行数
- `-f` = follow，实时跟踪文件新增内容，看日志必备
- `tail -n +5`（注意加号）= 从第 5 行开始到结尾

### 12.12 `ls -A` 与 `ls -a`

```bash
ls -A /data    # 列出所有条目，含隐藏文件，但不含 . 和 ..
ls -a /data    # 含隐藏文件，且包含 . 和 ..
```

- `-A` = almost all，判断"目录是否为空"时用 `-A` 更准（`. ` 和 `..` 会让 `-a` 永远有输出）

### 12.13 `systemctl` 相关

```bash
sudo systemctl daemon-reload          # 重读所有单元配置（改 fstab/unit 文件后必做）
systemctl --failed                    # 列出处于 failed 状态的单元
systemctl status data.mount --no-pager   # 查某单元状态，不分页
systemctl mask data.mount             # 彻底屏蔽，连手动 start 都拒绝
systemctl unmask data.mount           # 解除屏蔽
```

| 概念 | 含义 |
|---|---|
| `daemon-reload` | 只重读配置，**不启动也不停止**任何服务，所以改完还要 `mount -a` / `restart` |
| `--failed` | 只看失败单元。**注意**：从没启动过的单元是 `inactive (dead)`，不算 failed |
| `--no-pager` | 不要用 `less` 分页，直接一次性输出（脚本/复制时要加） |
| `mask` | 比 `disable` 更狠，软链到 `/dev/null` |

### 12.14 `journalctl` 的过滤参数

```bash
sudo journalctl -xb                    # 本次开机的日志，含 systemd 提示
sudo journalctl -b -u data.mount -n 30 --no-pager
sudo journalctl --since "10 min ago"
sudo journalctl -p err                 # 只显示 error 及以上
```

| 参数 | 含义 |
|---|---|
| `-b` | boot，只看本次开机；`-b -1` 是上一次开机 |
| `-x` | 附带解释性帮助文字（"这个报错的常见原因"） |
| `-u 单元` | unit，只看某个 systemd 单元 |
| `-n 30` | 最后 30 行 |
| `-p` | priority，按日志级别过滤（`err`、`warning`、`info`） |
| `--no-pager` | 不分页 |

- **必须 `sudo`**：普通用户看系统日志会被 PAM 拦住。把用户加进 `adm` 或 `systemd-journal` 组可以免 sudo：`sudo usermod -aG adm madrough`（**改完要重新登录**）

### 12.15 `ss` — 查端口与连接

```bash
sudo ss -tlnp | grep :22
```

| 参数 | 含义 |
|---|---|
| `-t` | TCP |
| `-u` | UDP（常用组合是 `-tulnp`） |
| `-l` | listening，只看监听中的 |
| `-n` | numeric，端口显示数字而不是服务名（`22` 而不是 `ssh`） |
| `-p` | process，显示占用端口的进程（**需要 root**） |

- **意义**：判断"服务到底起没起"最直接的证据。`Connection refused` 时第一件事就是这条
- 输出里的 `users:(("sshd",pid=...,fd=...))` 告诉你谁在占用

### 12.16 shell 的 `for` 循环（一行式）

```bash
for h in /sys/class/scsi_host/host*/scan; do echo "- - -" | sudo tee $h; done
```

拆开看：

| 部分 | 含义 |
|---|---|
| `for h in 列表` | 遍历列表，每次把一项赋给变量 `h` |
| `/sys/class/scsi_host/host*/scan` | 通配符展开成多个路径 |
| `do ... done` | 循环体 |
| `$h` | 引用变量 |

- **这条的具体作用**：往每个 SCSI 主机的 `scan` 文件写 `- - -`，触发重新扫描总线 → 热添加的磁盘被识别
- `- - -` 三个占位符分别代表 channel / target / LUN，`-` 表示"任意"

### 12.17 内核参数（GRUB 里加的）

| 参数 | 作用 |
|---|---|
| `systemd.mask=data.mount` | 启动时屏蔽该单元，等于跳过这个挂载 |
| `init=/bin/bash` | 不启动 systemd，直接进 root shell（救援用） |
| `rw` | 根文件系统以可读写方式挂载 |
| `single` / `rescue` | 进单用户/救援模式 |
| `systemd.unit=emergency.target` | 直接进 emergency 模式 |

加的位置：GRUB 菜单按 `e` → `linux ...` 那一行**行尾**追加 → `Ctrl+X` 启动。**临时生效，不改磁盘配置。**

### 12.18 VMware 控制台按键

| 按键 | 作用 |
|---|---|
| `Ctrl+Alt+Space` 然后 `F1`~`F6` | 切到虚拟终端 1~6（`Ctrl+Alt+F1` 会被宿主机抢走） |
| `Ctrl+Alt+Space` 然后 `Enter` | 发送回车给虚拟机 |
| `Ctrl+Alt` | 释放鼠标（让鼠标回到宿主机） |
