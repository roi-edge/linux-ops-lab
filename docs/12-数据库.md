> 实验日期：2026-11-08

## 一、目标与验收

**做：** 装 MySQL，建库建用户，限制只允许本地 + 指定 IP 连接

**验收：** 从另一台机器连不上、从本机连得上；能解释 `bind-address`

**结论：** 达成。核心产出是 **"三层门"模型**（第四节 4.1）：`bind-address` / `ufw` / `user@host` 三层**互相独立**，每层失败的现象和排查手段都不同。另外撞到一个非常隐蔽的坑 —— **自建 DNS 的 PTR 记录让 MySQL 把客户端 IP 反解成 `www.lab.local`**，导致账号匹配对不上（4.4）。

```powershell
# 身份：Windows 宿主机（PowerShell）
```

**实测：**

```
Port 3306 → PingSucceeded : True

```

**`PingSucceeded : True` + `TcpTestSucceeded : False` = 机器活着、网络通、只是这个端口没人接。** 而且**几乎立刻返回** → 是 **RST（拒绝）**，不是超时。

**为什么要先测 22**：它是**对照组**。没有它，"3306 不通"可以被解释成"Windows 根本连不上那台机器"，那就什么都没证明。

### 3.6 打开第一层门：改 `bind-address`

```bash
# 身份：madrough @ ubuntulearn（普通用户，sudo 提权）
madrough@ubuntulearn:~$ sudo mkdir -p /root/lab12
madrough@ubuntulearn:~$ sudo cp -a /etc/mysql/mysql.conf.d/mysqld.cnf /root/lab12/mysqld.cnf.orig
madrough@ubuntulearn:~$ sudo sed -i 's/^bind-address\s*=\s*127\.0\.0\.1/bind-address = 192.168.9.50/' /etc/mysql/mysql.conf.d/mysqld.cnf
madrough@ubuntulearn:~$ sudo sed -i 's/^mysqlx-bind-address\s*=\s*127\.0\.0\.1/mysqlx-bind-address = 192.168.9.50/' /etc/mysql/mysql.conf.d/mysqld.cnf
madrough@ubuntulearn:~$ sudo diff /root/lab12/mysqld.cnf.orig /etc/mysql/mysql.conf.d/mysqld.cnf
madrough@ubuntulearn:~$ sudo systemctl restart mysql
madrough@ubuntulearn:~$ sudo ss -tlnp | grep -E ':3306|:33060'
madrough@ubuntulearn:~$ sudo mysql -e "SELECT @@bind_address;"
```

**为什么绑 `192.168.9.50` 而不是 `0.0.0.0`**：`0.0.0.0` 是**所有地址**，包括以后 Docker 起出来的 `172.17.0.1` 和任何新增网卡。绑具体地址是生产规范（与实验 08"后端别绑 `0.0.0.0`"同一个道理）。

**为什么要 `restart` 不能 `reload`**：`bind_address` 决定启动时在哪建监听 socket，运行中改不了。


**实测：`TcpTestSucceeded=False   耗时=21.1s`**

| 时刻 | MySQL 监听 | ufw | 耗时 | 失败性质 |
|---|---|---|---|---|
| 3.5 | `127.0.0.1:3306` | 无 3306 规则 | **几乎立刻** | **RST（拒绝）** |


**实测：**

```
-A ufw-user-input -s 192.168.9.0/24 -p tcp -m tcp --dport 3306 -j ACCEPT
```

**"放行"和"对谁放行"是两件事，后者才是安全性的全部。** `ufw allow 3306/tcp`（对 Anywhere）是危险的。

### 3.8 复测 + 对照（证明放行的是"端口"不是"服务"）

```powershell

PS C:\> $sw=[Diagnostics.Stopwatch]::StartNew(); $r2=Test-NetConnection -ComputerName 192.168.9.50 -Port 33060 -InformationLevel Quiet; $sw.Stop(); "33060 -> $r2  $([math]::Round($sw.Elapsed.TotalSeconds,2))s"
```

### 3.9 第三层门（账号层）：三种连法，三种结果

```bash
# 身份：madrough @ ubuntulearn（普通用户）
madrough@ubuntulearn:~$ mysql -u lab -p'<DB_PASSWORD>' -e "SELECT CURRENT_USER() AS matched_as, USER() AS claimed_as, @@port AS port;"
madrough@ubuntulearn:~$ mysql -h 192.168.9.50 -u lab -p'<DB_PASSWORD>' -e "SELECT 1;"
madrough@ubuntulearn:~$ mysql -h 127.0.0.1 -u lab -p'<DB_PASSWORD>' -e "SELECT 1;"
```

**实测：**

| # | 连法 | 结果 |
|---|---|---|
| 1 | 不写 `-h`（**Unix socket**） | ✅ `matched_as = lab@localhost`，`claimed_as = lab@localhost` |
| 2 | `-h 192.168.9.50`（TCP） | ❌ **`ERROR 1130 (HY000): Host 'www.lab.local' is not allowed to connect`** |
| 3 | `-h 127.0.0.1`（TCP，那个地址没人监听） | ❌ **`ERROR 2003 (HY000): Can't connect ... (111)`** |

**第 2 条报的是 `www.lab.local` 而不是 `192.168.9.50`** —— 这就是 4.4 那个坑的现场。

```bash
madrough@ubuntulearn:~$ sudo mysql -e "SHOW VARIABLES LIKE 'skip_name_resolve';"
```

### 3.14 对照：删掉账号，同一台 Windows 变成了拒绝

```bash
# 身份：madrough @ ubuntulearn（普通用户，sudo 提权）
madrough@ubuntulearn:~$ sudo mysql <<'SQL'
DROP USER 'lab'@'192.168.9.1';
TRUNCATE performance_schema.host_cache;
SELECT user, host FROM mysql.user WHERE user='lab' ORDER BY host;
SQL
```

**Windows 侧再读一次（同 3.13 的命令）：**

```
0x44 0x00 0x00 0x00 0xFF 0x6A
payload首字节=0xFF   payload长度=68
D?jHost '192.168.9.1' is not allowed to connect to this MySQL server
```

| 字节 | 含义 |
|---|---|
| `0x44 0x00 0x00` | payload 长度 68 |
| `0x00` | 序号 |
| **`0xFF`** | **ERR 包**（不是握手） |
| `0x6A` | 错误码 **1130 = `0x046A`**，小端序 → `6A 04` |
| ASCII 文本 | ERR 包里的错误消息是**明文 ASCII**，所以不装客户端也能读到人话 |

**同一台 Windows、同一端口、同一路径，只因为账号表里少了一行，`0x0A` 变成了 `0xFF`。**

## 四、原理

### 4.1 三层门（本项的核心模型）

```
Windows (192.168.9.1)
      │  ① 网络层：包能不能到达 MySQL 进程
      ├──── bind-address（MySQL 在哪个 IP 上 listen）
      ├──── ufw（包允不允许进来）
      ▼
   192.168.9.50:3306
      │  ② 连接层：连上之后给不给握手
      ├──── mysql.user 里有没有这个「来源主机」的记录
      ▼
   MySQL 握手（0x0A）
      │  ③ 认证层：握手之后能不能认证成功
      ├──── 用户名 + 密码 + 认证插件（caching_sha2_password）
      ▼
   成功 / 1045 Access denied
```

| 层 | 失败现象 | 排查命令 |
|---|---|---|
| ① `bind-address` | **立即** `TcpTestSucceeded : False`（RST） | `ss -tlnp \| grep 3306`、`SELECT @@bind_address` |
| ① `ufw` | **等 21 秒** `TcpTestSucceeded : False`（DROP） | `ufw status`、`iptables -S ufw-user-input` |
| ② host ACL | TCP 通了，但第一个字节是 **`0xFF`** / 报 **1130** | `SELECT user, host FROM mysql.user`、`host_cache` |
| ③ 认证 | 报 **1045** / **2059** | 密码、`plugin` 列、`SHOW GRANTS` |

**这个模型的价值**：任何"连不上数据库"的问题，先判断卡在哪一层，**不要三层一起瞎试**。

### 4.2 MySQL 账号 = 用户名 + 来源主机

`'lab'@'localhost'` 和 `'lab'@'192.168.9.1'` 是**两个完全独立的账号**：密码可以不同、权限可以不同、可以单独删掉一个。

**匹配规则（重要）：**
- 如果有 `'lab'@'192.168.9.1'` 和 `'lab'@'%'` 两条，MySQL 选**更具体的**（IP 比 `%` 具体）
- `%` 会接住**所有你没预料到的来源** —— 这才是它的危险之处

**host 的三种写法：**

| 写法 | 含义 |
|---|---|
| `'192.168.9.1'` | 精确 IP |
| `'192.168.9.%'` | 整个网段（内网应用常用） |
| `'%'` | **任意主机，包括公网**（业务账号禁用） |
| `'localhost'` | **仅 Unix socket 连接**（不是 `127.0.0.1`！见 4.3） |

### 4.3 socket 和 TCP 是两条路，`localhost` 只属于 socket

| 连法 | 走的通道 | 匹配的 host |
|---|---|---|
| `mysql -u lab`（不写 `-h`） | **Unix socket** `/var/run/mysqld/mysqld.sock` | `localhost` |
| `mysql -h 127.0.0.1` | TCP 到回环地址 | `127.0.0.1` |
| `mysql -h 192.168.9.50` | TCP 到本机网卡地址 | `192.168.9.50`（或反解出的域名） |

**所以最常见的坑是**：只建了 `'user'@'localhost'`，然后用 `-h 127.0.0.1` 连 → **1130**。看起来"我明明建了 localhost 的账号"，但 `127.0.0.1` 和 `localhost` 在 MySQL 眼里是**两个不同的 host**。

### 4.4 反向解析：本项最大的坑（与实验 10 联动）

**MySQL 默认 `skip_name_resolve = OFF`**，即：每来一个新客户端 IP，它先做一次 **PTR 反解**，把 IP 变回域名，再拿域名去匹配 `mysql.user.host`。

本机的实际链条：

```
从 192.168.9.50 连 MySQL
   → MySQL 拿 192.168.9.50 查 PTR
   → systemd-resolved → dnsmasq
   → dnsmasq 的 host-record=www.lab.local,192.168.9.50 自动生成了 PTR
   → 返回 www.lab.local
   → MySQL 拿 "www.lab.local" 去匹配 mysql.user.host
   → 账号表里只有 localhost / 192.168.9.50 → 匹配失败
   → ERROR 1130 Host 'www.lab.local' is not allowed
```

**实验 10 里一条 `host-record`，改变了实验 12 里数据库的认证结果。** 这就是"服务之间隐性耦合"的真实例子。

### 4.5 `1130` / `1045` / `2003` 三个错误码分清楚

| 错误码 | 文案 | 哪一层 | 含义 |
|---|---|---|---|
| **2003** | `Can't connect to MySQL server on 'x:3306' (111)` | **连接层** | TCP 连不上：端口没监听 / 被防火墙挡 / 地址写错。`(111)` = ECONNREFUSED |
| **1130** | `Host 'x' is not allowed to connect` | **host ACL 层** | TCP 通了，但**这个来源主机在 `mysql.user` 里一条记录都没有**，握手之前就拒 |
| **1045** | `Access denied for user 'u'@'h' (using password: YES)` | **认证层** | 主机有记录，但**用户名/密码/插件**不匹配 |

> **1130 = 门都没让你进；1045 = 门进了但钥匙不对。** 网上大量帖子把这两个混着答，方向直接跑偏。

### 4.6 MySQL 的包结构：为什么不能看"首字节"

每个 MySQL 包都是 **4 字节头 + 负载**：

| 位置 | 内容 |
|---|---|
| 第 1~3 字节 | **负载长度**（小端序） |
| 第 4 字节 | **序号 sequence id** |
| 第 5 字节起 | 负载（握手包的第一个字节才是**协议版本 `0x0A`**；ERR 包的第一个字节是 `0xFF`） |

**实测握手包：**

```
0x5B 0x00 0x00 0x00 0x0A 0x38
└────┬────┘ └┬┘ └┬┘ └┬┘
 长度 91     序号 0 协议版本   '8'（版本串首字符）
91 + 4 = 95 = 实际收到的字节数
```

**所以判断"给不给握手"要看 `$b[4]`**：

| `$b[4]` | 含义 |
|---|---|
| `0x0A` | 握手包（协议版本 10） → 主机被允许 |
| `0xFF` | ERR 包 → 直接拒绝（1130 就在这里面） |

### 4.7 `caching_sha2_password`

MySQL 8 的默认认证插件。特点：

| 优势 | 代价 |
|---|---|
| 传输的是 SHA-256 挑战应答，**不发明文密码**；支持 TLS 下更安全 | **老客户端不认它**：PHP 5.x/7.0 早期、老版本 Navicat/Workbench 会报 `Authentication plugin 'caching_sha2_password' cannot be loaded` |

**兼容方案（按推荐顺序）：**

1. **升级客户端**（首选，别为了客户端降级服务端安全）
2. 对该账号改插件：`ALTER USER 'lab'@'x' IDENTIFIED WITH mysql_native_password BY '...'`（**`mysql_native_password` 在 8.0.34+ 已废弃，未来版本会移除，只是过渡手段**）
3. 用 TLS 连接（客户端仍要支持 caching_sha2）

### 4.8 为什么用 InnoDB

| 引擎 | 事务 | 行锁 | 崩溃恢复 | 结论 |
|---|---|---|---|---|
| **InnoDB** | ✅ | ✅ | ✅ | **默认、唯一正确选择** |
| MyISAM | ❌ | ❌（表锁） | ❌ | 只在极特殊场景用，一般不要 |

`ENGINE=InnoDB` 写出来是**显式声明**，避免被实例默认引擎（可能被人改过）影响。

## 五、生产实践（**实际工作中的正确做法**）

> 这一节是本项的"能落地"部分。实验里为了看到效果做的某些操作（命令行明文密码、`GRANT ALL`），**在生产里都是要被禁止或替换的**。

### 5.1 账号：最小权限 + 一账号一用途

| 做法 | 具体 |
|---|---|
| **一个应用一个账号** | 不要多个服务共用一个账号。出事时无法定位是谁、也无法单独吊销 |
| **只给需要的库、需要的操作** | 业务账号：`SELECT, INSERT, UPDATE, DELETE`；**不给** `DROP/ALTER/CREATE` |
| **禁止 `GRANT ALL ON *.*`** | 除 DBA 账号外一律禁止。业务账号拿到 `ALL ON *.*` = 等于 root |
| **禁止业务账号远程登录用 `root`** | `root` 只允许 `localhost`（Ubuntu 默认就是 `auth_socket`，这是对的） |
| **`%` 只在万不得已时用** | 优先精确 IP 或网段；用 `%` 必须配合 `bind-address` 和内网隔离 |
| **单独建备份账号** | 只有 `SELECT, LOCK TABLES, SHOW VIEW, RELOAD, REPLICATION CLIENT`，**不给写权限** |
| **单独建监控账号** | 只给 `PROCESS, REPLICATION CLIENT, SELECT on performance_schema` |

**推荐的最小权限模板：**

```sql
-- 业务账号：只在自己库上增删改查
CREATE USER 'app'@'192.168.9.%' IDENTIFIED BY '<强密码>';
GRANT SELECT, INSERT, UPDATE, DELETE ON `appdb`.* TO 'app'@'192.168.9.%';

-- 只读报表账号
CREATE USER 'report'@'192.168.9.%' IDENTIFIED BY '<强密码>';
GRANT SELECT ON `appdb`.* TO 'report'@'192.168.9.%';

-- 备份账号（mysqldump --single-transaction 需要这些）
CREATE USER 'backup'@'localhost' IDENTIFIED BY '<强密码>';
GRANT SELECT, LOCK TABLES, SHOW VIEW, EVENT, TRIGGER ON *.* TO 'backup'@'localhost';
REQUIRE SSL;   -- 生产建议加，强制加密
```

**定期审计（上线后每月至少一次）：**

```sql
-- 谁有超级权限（应该只有 1~2 个）
SELECT user, host FROM mysql.user WHERE Super_priv='Y';
-- 谁没有任何密码 / 谁用旧插件
SELECT user, host, plugin, password_expired FROM mysql.user;
-- 谁从任何主机都能连（高危）
SELECT user, host FROM mysql.user WHERE host IN ('%', '');
```

### 5.2 `bind-address`：只绑需要的地址

| 场景 | 写法 |
|---|---|
| 数据库只给本机应用用（**最常见、最安全**） | `bind-address = 127.0.0.1` |
| 数据库要给内网另一台应用服务器用 | `bind-address = <内网 IP>`（**不是 `0.0.0.0`**） |
| 除非有专门的内网隔离，**不要 `0.0.0.0`** | `0.0.0.0` = 包括 Docker 网桥、IPv6、任何新加网卡全暴露 |

**配套**：只开 `3306`，**`33060`（X Protocol）用不到就别开**。

### 5.3 防火墙：限定来源，而不是"放行端口"

```bash
# ❌ 不推荐
ufw allow 3306/tcp

# ✅ 推荐：只让应用服务器所在网段进
ufw allow from 192.168.9.0/24 to any port 3306 proto tcp
# 或精确到单机
ufw allow from 192.168.9.30 to any port 3306 proto tcp
```

**云上还有第二层**：安全组（见实验 25）。**安全组 + ufw 两层都要配，缺一层就等于没配。**

### 5.4 `skip_name_resolve = ON`：生产必开（本项最大的生产结论）

```ini
# /etc/mysql/mysql.conf.d/mysqld.cnf
[mysqld]
skip_name_resolve = ON
```

**为什么必须开：**

| 理由 | 后果 |
|---|---|
| **① 反解给每次新连接加延迟** | 每个新 IP 都要一次 PTR 查询（缓存 30 秒）。DNS 慢 200ms，建连就慢 200ms；高并发下是实打实的性能损耗 |
| **② DNS 故障 → 数据库拒绝服务** | 反解依赖 DNS。**DNS 挂了，MySQL 认不出客户端，全部连接失败**。数据库可用性被一个无关服务拖死 |
| **③ 反解结果可被篡改，账号匹配不可预测** | 本次实测：自建 DNS 一条 `host-record` 就让 host 从 IP 变成了 `www.lab.local`。**能不能登录取决于 DNS 里写了什么**，安全上不可接受 |
| **④ 反解失败会直接报错** | 日志里常见 `Got error 1130` / `Host ... is not allowed`，查半天发现是 DNS 的问题 |

**开了之后必须遵守的两条规则：**

1. **账号表里不能再写域名**（`'app'@'db.example.com'` 会失效），只能用 **IP、`localhost`、`%`、网段**。
2. **`localhost` 仍然有效**（Unix socket 连接不受影响）。

**验证：**

```sql
SHOW VARIABLES LIKE 'skip_name_resolve';   -- 必须是 ON
```

### 5.5 密码管理：绝不出现在命令行

| ❌ 不要 | ✅ 要 |
|---|---|
| `mysql -u app -p'密码'`（`ps aux` 全世界可见，还会进 `.bash_history`） | `mysql --login-path=app`（`mysql_config_editor` 生成的加密凭据） |
| 密码写进脚本 | `~/.my.cnf` 且 **`chmod 600`**，或用环境变量 + 受限 shell |
| 多个服务共用一个密码 | 一账号一密码，定期轮换 |
| 弱密码 / 有规律的密码 | 16 位以上随机；用密码管理器 |

**`mysql_config_editor` 的正确用法（推荐）：**

```bash
# 一次性录入（密码不会出现在命令行，也不会进 history）
mysql_config_editor set --login-path=app --user=app --password
# 之后这样用，命令行里看不到任何密码
mysql --login-path=app -e "SELECT 1"
```

**`~/.my.cnf` 写法（次选，权限必须 600）：**

```ini
[client]
user=app
password=<密码>
host=192.168.9.50
```

```bash
chmod 600 ~/.my.cnf      # 不做这一步等于把密码公开
```

**密码策略（MySQL 8 自带组件）：**

```sql
INSTALL COMPONENT 'file://component_validate_password';
SHOW VARIABLES LIKE 'validate_password%';
-- 默认要求：长度>=8、含大小写/数字/特殊字符
```

### 5.6 变更权限后为什么要清 `host_cache`

```sql
TRUNCATE performance_schema.host_cache;
```

MySQL 把"某个 IP 能不能连"缓存在 `host_cache` 里（默认 30 秒）。**改完权限/删完账号不清缓存，可能看到旧行为** —— 表现为"明明改了却不生效"，是排查权限问题时的经典陷阱。

**`host_cache` 还能当排障工具用**：`COUNT_HOST_ACL_ERRORS`（主机被拒次数）、`COUNT_AUTHENTICATION_ERRORS`（认证失败次数）能直接告诉你"是主机层被拒还是密码错"。

### 5.7 日志与审计

| 日志 | 位置 | 用途 |
|---|---|---|
| 错误日志 | `/var/log/mysql/error.log` | **启动失败、崩溃、1130/1045 都会记** |
| 慢查询日志 | 默认关，`slow_query_log = ON` + `long_query_time = 1` | 找性能瓶颈的第一手材料 |
| 通用查询日志 | 默认关，**生产别开**（写所有语句，IO 和磁盘爆炸） | 只在临时排障时开几分钟 |
| 审计日志 | 需装 `audit_log` 插件（企业版/第三方） | 合规场景（等保、金融）必须 |

**至少要做**：错误日志纳入监控，慢查询日志开启并定期分析。

### 5.8 备份要先验证能恢复

- `mysqldump --single-transaction`（InnoDB 不锁表）+ `--routines --triggers`
- **定期做恢复演练**——备份文件能生成 ≠ 能恢复。实验 13 会专门做这项
- 大库用 `xtrabackup`（物理备份），`mysqldump` 在几十 G 以上会非常慢

### 5.9 版本与升级

| 做法 | 说明 |
|---|---|
| 用发行版仓库 / 官方 APT 源，别用编译安装 | 便于安全更新 |
| 关注 CVE，及时打小版本 | `apt upgrade` 即可 |
| **大版本升级前先在快照/从库演练** | MySQL 5.7→8.0 有大量不兼容（默认认证插件、`GROUP BY` 隐式排序移除、保留字变化） |
| 升级前跑 `mysqlcheck` + `mysql_upgrade`（8.0 已内置自动升级） | — |

### 5.10 资源与容量

| 项 | 建议 |
|---|---|
| `innodb_buffer_pool_size` | **物理内存的 50%~70%**（专用数据库机）。默认值很小，是最常见的性能瓶颈 |
| `max_connections` | 按应用连接池总量估算，**不是越大越好**（每个连接都吃内存） |
| 磁盘 | 数据 + binlog + 慢日志都要预留；**监控 80% 告警**（实验 24 会做） |
| binlog 保留 | `binlog_expire_logs_seconds` 设 7 天左右，否则 binlog 会把磁盘吃满 |

## 六、踩坑清单

| # | 坑 | 说明 / 正确做法 |
|---|---|---|
| 1 | 只改 `bind-address`，忘了 `mysqlx-bind-address` | 33060（X Protocol）还在旧地址监听。**两行一起改** |
| 2 | 改完 `bind-address` 用 `systemctl reload` | 不生效。**`bind_address` 是启动参数，必须 `restart`** |
| 3 | 绑了 `192.168.9.50` 后测 `-h 127.0.0.1` 失败，以为配错了 | **正常**。绑具体地址就意味着其他地址不再监听 |
| 4 | `ufw allow 3306`（不放来源） | 对 Anywhere 开放，等于把数据库暴露给整个网络。**用 `from <网段>`** |
| 5 | 只看 `TcpTestSucceeded: False` 就下结论 | **要看耗时**：立即失败 = RST（端口没开）；等 21 秒 = DROP（防火墙） |
| 6 | 建了 `'user'@'localhost'`，却用 `-h 127.0.0.1` 连 | `localhost`（socket）和 `127.0.0.1`（TCP）是**两个不同 host** |
| 7 | 报 `1130 Host 'xxx' is not allowed` 就去查密码 | **1130 跟密码无关**，是"这个来源主机没有任何账号记录"。查 `mysql.user` 的 host 列 |
| 8 | 报 `1045 Access denied` 却去查防火墙 | 1045 是**认证失败**（密码/用户名/插件），网络早就通了 |
| 9 | 以为 `GRANT USAGE ON *.*` 是给了权限 | **`USAGE` = 零权限**，只表示"能登录" |
| 10 | MySQL 报的 host 是域名而不是 IP，查半天 | `skip_name_resolve=OFF` 时会做 PTR 反解。**开 `skip_name_resolve=ON`**（本次实测：自建 DNS 的 PTR 让 host 变成 `www.lab.local`） |
| 11 | 改完权限"不生效" | 清 `host_cache`（30 秒缓存）：`TRUNCATE performance_schema.host_cache` |
| 12 | 命令行 `mysql -p'密码'` | 密码进 `ps`、进 history。用 `mysql_config_editor` / `~/.my.cnf`（chmod 600） |
| 13 | 关反向解析后账号里还写域名 | `skip_name_resolve=ON` 后**域名 host 全部失效**，只能用 IP/localhost/% |
| 14 | 老客户端连 MySQL 8 报 `caching_sha2_password cannot be loaded` | 升级客户端；或临时改 `mysql_native_password`（已废弃，只是过渡） |
| 15 | 以为是 bind 问题，其实是 3306 被 MariaDB 占了 | 装之前先 `ss -tlnp \| grep 3306` |
| 16 | 看 MySQL 包"首字节"判断类型 | **前 3 字节是长度、第 4 字节是序号**，类型在**第 5 字节**（`$b[4]`） |

## 七、命令详解（本项首次出现）

### 7.1 安装与系统层

| 命令 / 参数 | 是什么 → 干什么 → 为什么这里用 |
|---|---|
| `apt-cache policy mysql-server` | 看包**候选版本、已装版本、来源仓库** → 装前确认没装过、版本符合预期 |
| `dpkg -l \| grep -c 'mysql\|mariadb'` | `-c` 只输出**匹配行数** → 快速判断"是不是干净的机器" |
| `systemctl list-unit-files` | 列出所有单元及其启用状态 → 确认没有 `mariadb.service` 抢占 3306 |
| `du -sh /var/lib/mysql` | `-s` 汇总、`-h` 人类可读 → 看数据目录初始大小，为容量规划留基线 |
| `dnf/apt install -y` | `-y` 跳过 apt 自己的确认（**不跳过软件包 postinst 的提示**） |

### 7.2 MySQL 客户端与 SQL

| 命令 / 参数 | 是什么 → 干什么 → 为什么这里用 |
|---|---|
| `sudo mysql` | Ubuntu 下 root 走 **`auth_socket`**，只要你是本机 sudo 用户就免密进 → 不用管 root 密码 |
| `mysql -e "SQL"` | `-e` 执行一条语句后退出（非交互） → 脚本化、贴日志方便 |
| `mysql <<'SQL' ... SQL` | **heredoc** 把多行 SQL 喂给 stdin → 多语句脚本，比 `-e` 可读 |
| `mysql -h <主机>` | `-h` 指定**主机**。不写 = 走 Unix socket；写 IP = 走 TCP → **这是本项区分三层门的关键开关** |
| `mysql -u <用户>` | 指定用户名 |
| `mysql -p'密码'` | `-p` 与密码之间**不能有空格**（有空格会被当数据库名）；**会被 `ps` 看到** → 生产别用 |
| `SELECT CURRENT_USER()` | **服务器实际匹配到的账号**（权限按它算） |
| `SELECT USER()` | **客户端声称的身份** → 两者不一致时说明 host 匹配/反解发生了 |
| `SELECT @@bind_address` | 系统变量，`@@` 前缀表示"服务器变量" |
| `SHOW VARIABLES LIKE 'x'` | 查运行时参数值 → 确认配置真的生效（比看配置文件可靠） |
| `SHOW GRANTS FOR 'u'@'h'` | 打印某账号的全部授权 **+ 它匹配到的所有角色** |
| `\G`（语句结束符） | 代替 `;`，**结果竖向排列** → 列多时比宽表好读 |
| `CREATE DATABASE ... CHARACTER SET utf8mb4` | **`utf8mb4` 才是真 UTF-8**（老 `utf8` 只有 3 字节，存 emoji 会报错） |
| `COLLATE utf8mb4_0900_ai_ci` | `ai` 不分重音、`ci` 不分大小写；MySQL 8 默认排序规则 |
| `CREATE USER 'u'@'h' IDENTIFIED BY 'p'` | 建账号。**host 是身份的一部分**，同名不同 host 是不同账号 |
| `GRANT 权限 ON 库.表 TO 'u'@'h'` | 授权。`*.*` = 所有库所有表；`db.*` = 该库所有表 |
| `DROP USER 'u'@'h'` | 删账号，**连带删掉它的所有授权**（比 `REVOKE` 彻底） |
| `TRUNCATE performance_schema.host_cache` | 清空主机缓存（默认 30 秒）→ 改完权限/删完账号后强制重新判断 |
| `SELECT * FROM performance_schema.host_cache\G` | 看每个客户端 IP 的**反解结果**和各类错误计数（`COUNT_HOST_ACL_ERRORS` 等）→ 定位"是主机层还是密码层被拒" |
| `ENGINE=InnoDB` | 指定存储引擎。InnoDB 支持**事务 + 行锁 + 崩溃恢复**，是默认且正确的选择 |

### 7.3 网络连通性测试（Windows / Linux）

| 命令 / 参数 | 是什么 → 干什么 → 为什么这里用 |
|---|---|
| `Test-NetConnection -ComputerName X -Port N` | PowerShell 内置，**测 TCP 端口**（不是 ping）→ 判断"端口开不开" |
| `-InformationLevel Quiet` | 只返回 `True`/`False` → 省掉大段输出，方便量时间 |
| `[System.Diagnostics.Stopwatch]::StartNew()` | .NET 秒表 → **量握手耗时，区分 RST 和 DROP** |
| `$sw.Elapsed.TotalSeconds` | 取出总秒数 |
| `[math]::Round(x,1)` | 四舍五入到 1 位小数 |
| `New-Object Net.Sockets.TcpClient` | .NET 的 TCP 客户端 → 裸 TCP 连接，不依赖任何数据库客户端 |
| `$c.Connect(host,port)` | 发起三次握手 |
| `$s.GetStream()` | 取双向字节流 |
| `$s.ReadTimeout = 3000` | **读超时**（毫秒）→ 不加会永久阻塞卡死终端 |
| `New-Object byte[] 200` | 200 字节缓冲区 |
| `$s.Read($b,0,200)` | 阻塞读，返回实际读到的字节数 |
| `'0x{0:X2}' -f $b[0]` | 格式化：`X2` = 十六进制、大写、补零两位 |

| `-join ' '` | 用空格拼接数组 |
| `$b[1]*256 + $b[2]*65536` | **小端序拼装**：网络协议里长度字段几乎都是低位在前 |
| `dig -x <IP> +short` | `-x` = **反向查询**（IP → PTR 域名）→ 验证"MySQL 报的域名从哪来" |
| `dig +time=N +tries=N` | 每次最多等 N 秒、最多重试 N 次 → 避免 DNS 不通时卡住 |
| `ss -tlnp \| grep :3306` | 看 3306 到底在**哪个地址**上监听（`127.0.0.1` 还是 `192.168.9.50`） |

### 7.4 配置编辑

| 命令 / 参数 | 是什么 → 干什么 → 为什么这里用 |
|---|---|
| `sed -i 's/^bind-address\s*=\s*127\.0\.0\.1/.../' f` | `^` 锚定行首（**避免误伤 `mysqlx-bind-address`**）、`\s*` 匹配任意空白、`\.` 转义点号 |
| `sed -i '/^\[mysqld\]/a skip_name_resolve = ON' f` | **`a` = 在匹配行之后 append** → 把配置插进正确的**段（section）**里。MySQL 的配置按段解析，插错段等于没写 |
| `sed -i 's/旧/新/g'` | `g` = 一行内全部替换 |
| `diff 旧 新` | 逐行比较 → **确认改动范围**。有差异时**退出码 1 是正常的** |
| `grep -vE '^\s*#\|^\s*$' f` | `-v` 反向匹配（去掉注释行和空行）、`-E` 扩展正则 → 只看**真正生效**的配置行 |

## 八、验收记录

| 验收项 | 结果 |
|---|---|
| 装 MySQL、建库建用户 | ✅ MySQL **8.0.46**，`labdb` + `t_hello`，3 个 `lab` 账号（localhost / `.50` / `.1`） |
| **限制只允许本地 + 指定 IP 连接** | ✅ 三层门全部实测：`bind-address=192.168.9.50`、`ufw` 只放 `192.168.9.0/24`、`mysql.user` 里按 host 精确限定 |
| **从另一台机器连不上** | ✅ Windows（`192.168.9.1`）三阶段实测：改 bind 前**立即 RST** → 改 bind 后 **21.1s 超时（ufw DROP）** → 放行后 **0.01s 通**；账号层删掉 `'lab'@'192.168.9.1'` 后，Windows 收到的第一个负载字节是 **`0xFF`** 且错误文本为 `Host '192.168.9.1' is not allowed` |
| **从本机连得上** | ✅ socket（`lab@localhost`）与 TCP（`lab@192.168.9.50`）都成功，`CURRENT_USER()` 分别正确 |
| **能解释 `bind-address`** | ✅ 见 4.1 三层门：`bind-address` 决定"进程在哪个 IP 上 listen"，是**第一层**；`127.0.0.1` = 只本机，`0.0.0.0` = 所有地址（含 Docker 网桥），绑具体内网 IP = 只对外必要的那条 |

**一句话总结（面试可用）：**

> 我用 MySQL 8 做了"只允许本地 + 指定 IP"的访问控制，抓到的是**三层门**：`bind-address` 决定在哪个地址监听（配错表现为 TCP 立即被 RST）、`ufw` 决定包能不能进来（表现为干等 21 秒超时）、`mysql.user` 的 `user@host` 决定连上之后给不给握手（表现为 `0xFF`/1130）。排查时先看耗时区分前两层，再看 `host_cache` 的 `COUNT_HOST_ACL_ERRORS` 区分后两层。过程中发现 MySQL 默认的反向解析让客户端 IP 被解析成域名（自建 DNS 的 PTR 记录导致），账号匹配对不上，最终按生产规范打开 `skip_name_resolve=ON`。
