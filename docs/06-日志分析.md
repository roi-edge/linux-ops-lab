## 二、查出的结论

### 2.1 上次开机（`-b -1`）失败的服务

```bash
sudo journalctl -b -1 -p err --no-pager
```

只有 4 行：

```

Oct 31 03:47:54 kernel: [Firmware Bug]: cpu 1, try to use APIC520 ...     ← VMware 噪音

Oct 31 04:06:57 systemd[1]: Failed to start lab05-crash.service - Lab05 Crash Loop Demo.  ← 05 实验痕迹
```

```bash
sudo journalctl -b -1 --no-pager | grep -i "Failed to start"
# Oct 31 04:06:57 systemd[1]: Failed to start lab05-crash.service - Lab05 Crash Loop Demo.
```

```bash
systemctl --failed
# 0 loaded units listed.
```

**结论：上次开机没有真正失败的系统服务。** 唯一的 `Failed to start` 是 05 手工启动的 `lab05-crash` 演示单元（没 `enable`，不是开机自启）。当前这次开机也是干净的。

**这是完整答案，不是"没找到"。** 汇报时要说清范围与依据：`-b -1`（上次开机）+ `-p err`（error 及以上）+ `grep "Failed to start"`。

> **认知**：`-p err` 里出现 `[Firmware Bug]`、`SMBus Host Controller not enabled` 这类是 **VMware 虚拟机的固定噪音**，任何 VMware 上的 Linux 都有，可以忽略。**err 级别不等于一定有故障。**

## 三、环境摸底

```bash
journalctl --disk-usage        # Archived and active journals take up 70.1M
ls -ld /var/log/journal        # drwxr-sr-x+ 3 root systemd-journal  → 持久化已开启
journalctl --list-boots        # 12 次开机（-11 ~ 0）
grep -v '^#' /etc/systemd/journald.conf | grep -v '^$'   # 只有 [Journal]，全默认
```

### 3.1 持久化决定"能不能查历史"

| `/var/log/journal` | `Storage=` 行为 | 后果 |
|---|---|---|
| **存在** | `persistent` | 能查历史所有开机（`-b -1`、`-b -2`…） |
| **不存在** | `auto`（内存 `/run/log/journal`） | **一重启全丢**，`--list-boots` 只有一行 |

**Ubuntu Server 默认不持久化**。本机碰巧已开启（`/var/log/journal` 从 10-22 就在）。

**开启方法（本机没做，备查）：**

```bash
sudo mkdir -p /var/log/journal
sudo systemd-tmpfiles --create --prefix /var/log/journal
sudo systemctl restart systemd-journald
```

或在 `/etc/systemd/journald.conf` 里设 `Storage=persistent` 后重启 journald。

> **这是 06 的隐藏关卡**：不持久化的话，"找出上次开机失败的服务"根本无从查起。

### 3.2 `--list-boots` 的编号规则

| 编号 | 含义 |
|---|---|
| `0` | **当前**这次开机 |
| `-1` | 上一次 |
| `-2` | 上上次 |
| 正数 | 更早的（历史上曾用正数，现在通常只有 0 和负数） |

本机实测：

```
-1 d83516ef... Sat 2026-10-31 03:48:00 UTC Sat 2026-10-31 04:24:02 UTC
 0 67e1005e... Sun 2026-11-01 02:40:16 UTC Sun 2026-11-01 03:08:55 UTC
```

**注意**：`systemctl --failed` 只能看当前开机，**查历史必须用 `journalctl -b -N`**。

## 四、三种过滤维度

### 4.1 按时间：`--since` / `--until`

```bash
journalctl --since "2026-10-31 04:05:00" --until "2026-10-31 04:08:00"
journalctl --since "06:40"                       # 今天的 06:40（只写时刻）
journalctl --since "today"                       # 今天 00:00（单独用）
journalctl --since "yesterday"                   # 昨天 00:00（单独用）
journalctl --since "-40min"                      # 40 分钟前
journalctl --since "-2h"                         # 2 小时前
journalctl --since "2026-10-31 18:00" --until "2026-11-01 02:00"
```

**⚠️ 关键限制（本次踩到）**：**`today` / `yesterday` / `tomorrow` 不能和具体时刻拼接。**

```bash
journalctl --since "today 06:40"
# Failed to parse timestamp: today 06:40     ← 报错
```

正确写法二选一：只写时刻（隐含今天）`--since "06:40"`，或写完整日期 `--since "2026-11-01 06:40"`。

| 想要的 | 正确写法 |
|---|---|
| 今天 06:40 | `"06:40"` |
| 今天 00:00 | `"today"` |
| 昨天 18:00 | `"2026-10-31 18:00"`（必须完整日期） |
| 40 分钟前 | `"-40min"` |

### 4.2 按优先级：`-p`

syslog 标准级别，数字越小越严重：

| 数字 | 名称 | 简写 | 典型场景 |
|---|---|---|---|
| 0 | emergency | `emerg` | 内核 panic |
| 1 | alert | `alert` | 根文件系统损坏 |
| 2 | critical | `crit` | 硬件故障 |
| 3 | **error** | `err` | 服务启动失败 |
| 4 | **warning** | `warning` | 磁盘将满、配置弃用 |
| 5 | notice | `notice` | 登录、服务启停 |
| 6 | info | `info` | 大多数正常日志 |
| 7 | debug | `debug` | 默认不记录 |

```bash
journalctl -p err -b -1          # 上次开机的 err 及以上（含 0~3）
journalctl -p warning -b         # 本次开机的 warning 及以上（含 0~4）
journalctl -p 0..3 -b            # 显式范围，等价于 -p err
```

**`-p err` = "err 及更严重"（0~3），不是"只要 err"。**

**⚠️ `-p warning` 会漏掉 info/notice**——而"处理动作"往往记在 info 里（本次演练就漏了 `巡检脚本已介入处理`）。

### 4.3 按来源：`-u` / `-t` / 字段

```bash
journalctl -u lab05-crash -b -1          # 按 systemd 单元
journalctl -t CRON --since "06:40"       # 按 syslog identifier
journalctl -t lab06-drill --since "06:40"  # 一个标签聚齐一次事件
journalctl --grep="Start request repeated too quickly"
journalctl _PID=1433 -n 5
journalctl _COMM=sudo --since "06:40"
journalctl -F SYSLOG_IDENTIFIER | head -20   # 列出该字段所有取值
```

**`-u` 和 `-t` 的区别（高频混淆）：**

| 参数 | 匹配什么 | 例子 |
|---|---|---|
| `-u` | **systemd 单元名** | `-u lab05-crash`、`-u ssh` |
| `-t` | **syslog identifier**（程序自报的名字） | `-t CRON`、`-t sudo`、`-t kernel` |

`cron` 服务（`-u cron`）≠ 它输出的 `CRON[...]` 日志（`-t CRON`）。**有些日志不属于任何 unit，`-u` 找不到，只能用 `-t` 或字段过滤。**

**常用 journald 字段：**

| 字段 | 含义 |
|---|---|
| `_PID` | 进程 ID |
| `_UID` / `_GID` | 用户/组 ID |
| `_COMM` | 进程名（`sudo`、`bash`、`systemd`） |
| `_EXE` | 可执行文件路径 |
| `_SYSTEMD_UNIT` | 所属单元 |
| `PRIORITY` | 优先级数字 0~7 |
| `SYSLOG_IDENTIFIER` | 同 `-t` |
| `MESSAGE` | 日志正文 |

**`--grep` vs `| grep`：**

| | 在哪过滤 | 特点 |
|---|---|---|
| `--grep=` | journald 层面 | 只搜 `MESSAGE` 字段，更快，大数据量优势明显 |
| `\| grep` | 输出文本 | 可搜任意列（时间、主机名），但要把全部日志先读出来 |

## 五、输出格式：`-o`

```bash
journalctl -b -1 -o short-iso     # 2026-10-31T04:06:57+0000（带时区偏移）
journalctl -b -1 -o short-unix    # 1793507217.123456（秒，方便相减）
journalctl -b -1 -o short-precise # 带微秒
journalctl -b -1 -o cat           # 只有正文，无时间/主机名
journalctl -b -1 -o json-pretty   # JSON，脚本处理用
```

**`-o short-unix` 是算时间差的利器**（05 里算重启耗时就是用它）；`-o short-iso` 跨时区排查最清楚。

## 六、时区问题（本次暴露）

```bash
date
# Sun Nov  1 06:21:47 AM UTC 2026

timedatectl
# Time zone: Etc/UTC (UTC, +0000)
```

**这台机器是 UTC，人在这边是 UTC+8。**

- 你说的"昨晚 2 点"（北京时间）= UTC **前一天 18:00**
- 日志里的 `02:00 UTC` = 北京时间 **当天 10:00**

**排查习惯**：先 `date` / `timedatectl` 确认时区，再对时间。真实运维里"服务器 UTC、本地 UTC+8"是天天遇到的麻烦。

想改成本地时区：

```bash
sudo timedatectl set-timezone Asia/Shanghai
```

（本实验没改，保持 UTC 便于和日志对照。）

## 七、日志占用与清理

```bash
journalctl --disk-usage                    # 总占用（本机 70.1M）
sudo journalctl --vacuum-size=500M         # 收缩到 500M 以内
sudo journalctl --vacuum-time=7d           # 只留 7 天
sudo journalctl --vacuum-files=5           # 只留 5 个日志文件
```

**永久限制**写 `/etc/systemd/journald.conf`：

```ini
[Journal]
Storage=persistent
SystemMaxUse=1G
SystemMaxFileSize=100M
MaxRetentionSec=30day
```

> **真实故障提醒**：`Restart=always` 的服务崩溃时疯狂刷日志，一晚上能把 journal 涨到几十 G 撑爆根分区（05 的闸门就是防这个）。`SystemMaxUse` 是第二道保险。

## 八、日志体系：journald vs rsyslog

本机**两套都在跑**：

```
应用 →  syslog()/journal →  journald（二进制，/var/log/journal）
                              ↓ 可选转发
                           rsyslog → /var/log/syslog、auth.log、kern.log…
```

| | journald | rsyslog（传统 syslog） |
|---|---|---|
| 存储 | 二进制，按字段索引 | 纯文本文件 |
| 查询 | `journalctl` 强大过滤 | `grep`/`awk` 硬查 |
| 结构化 | 每条带字段（`_PID`、`_COMM`…） | 只有一行文本 |
| 轮转 | 自动（`SystemMaxUse`） | `logrotate` 配置 |

`/var/log/` 下的传统日志：

| 文件 | 内容 |
|---|---|
| `syslog` | 通用系统日志（rsyslog 汇总） |
| `auth.log` | 认证/登录（**查入侵必看**） |
| `kern.log` | 内核 |
| `dpkg.log` | 软件包安装记录 |
| `dmesg` | 内核环形缓冲（`dmesg` 命令） |
| `btmp` | 失败登录（`lastb` 读） |
| `wtmp` | 登录记录（`last` 读） |

**`auth.log` 是排查"谁在爆破 SSH"的第一现场**，`btmp` + `lastb` 能直接列出失败登录的 IP。

## 九、限时演练复盘（06 的验收）

**题目**：今天 06:44:00 ~ 06:46:30（UTC）之间发生了什么？

| 轮次 | 操作 | 结果 |
|---|---|---|
| 第 1 轮 | `--since "2026-10-31 06:44"` | ❌ **日期写错**（今天 11-01），窗口为空 |
| 第 2 轮 | `--since "2026-11-01 06:44" -p warning` | ✅ 找到 2 条模拟故障，正确识别 |
| 第 3 轮 | `--since "today 06:40"` | ❌ **语法错误**：`today` 不能拼接时刻 |
| 第 4 轮 | `--since "06:40"` + `-t lab06-drill` | ✅ 三条齐全 |

**暴露的三个真实问题：**

1. **手打日期是限时场景最大风险** → 用 `today` / `-40min` 相对写法，或先 `date`
2. **`-p warning` 漏掉 info 级"处理动作"** → 先宽后窄，别一上来就收窄
3. **记错语法**（`today 06:40`） → 不确定就先试一条 `--since "yesterday" | head -3`

### 1 分钟内回答"某时刻发生了什么"的套路

```bash
# 第 1 步：确认现在几点、时区
date

# 第 2 步：宽窗口看全貌（不加过滤）
sudo journalctl --since "-30min" --no-pager | tail -50

# 第 3 步：发现可疑来源后锁定
sudo journalctl -t <标签> --since "<时刻>" --no-pager
# 或 sudo journalctl -u <单元> --since "<时刻>" --no-pager

# 第 4 步：需要分类时再收窄
sudo journalctl --since "<时刻>" -p err --no-pager
```

**核心原则：先宽后窄，先看"谁在说话"，再决定过滤什么。**

## 十、踩坑清单

| # | 坑 | 正确做法 |
|---|---|---|
| 1 | 手打日期写错（10-31 写成今天是 11-01） | 用 `--since "-30min"` / `"06:40"` / 先 `date` 确认 |
| 2 | `--since "today 06:40"` 报 `Failed to parse timestamp` | `today`/`yesterday` 只能单独用；要时刻就只写 `"06:40"` 或完整日期 |
| 3 | 一上来就 `-p warning`，漏掉 info 级的处理记录 | 先不加过滤看全貌，再收窄 |
| 4 | 以为 `-p err` 只要 err | 实际是 err **及以上**（0~3） |
| 5 | 用 `systemctl --failed` 查历史 | 它只能看当前开机，历史用 `journalctl -b -N` |
| 6 | 查不到"上次开机" | `/var/log/journal` 不存在 = 没持久化，重启就丢 |
| 7 | 时间对不上 | 服务器 UTC、本地 UTC+8，先 `timedatectl` 确认 |
| 8 | `journalctl` 报 `Hint: ... not seeing messages` | 普通用户不在 `adm`/`systemd-journal` 组，加 `sudo` 或 `usermod -aG adm,systemd-journal 用户`（需重新登录） |
| 9 | 把 `[Firmware Bug]`、`SMBus ... not enabled` 当真故障 | VMware 虚拟机固定噪音，忽略 |
| 10 | 日志把磁盘撑满 | `SystemMaxUse=` 限制 + `journalctl --vacuum-size` 清理 |
| 11 | 以为 `-u cron` 能查到 `CRON[...]` 的日志 | 那是 `-t CRON`；`-u` 匹配单元，`-t` 匹配 `SYSLOG_IDENTIFIER` |

## 十一、命令详解（本项首次出现的命令与参数）

### 11.1 `journalctl` 全参数表

```bash
# 范围
journalctl -b              # 本次开机（-b -1 上次，-b -2 上上次）
journalctl --list-boots    # 列出所有开机
journalctl --since / --until
journalctl -n 50           # 最后 50 行（-n all 全部）
journalctl -f              # 实时跟随
journalctl -r              # 倒序（最新在前）

# 过滤
journalctl -u 单元         # 按 systemd 单元
journalctl -t 标签         # 按 SYSLOG_IDENTIFIER
journalctl -p err          # 按优先级（及以上）
journalctl --grep="文本"   # 按消息内容（正则）
journalctl _PID=1234       # 按字段
journalctl -F 字段         # 列出字段所有取值

# 输出
journalctl -o short-iso    # 输出格式
journalctl --no-pager      # 不分页（脚本/复制必加）
journalctl -q              # 去掉 "Hint:" 提示

# 维护
journalctl --disk-usage
journalctl --vacuum-size=500M
journalctl --vacuum-time=7d
journalctl --verify        # 校验日志文件完整性
```

**`-n` / `-r` / `--no-pager` 是日常三件套**；`-q` 专门对付那条烦人的 `Hint: ... not seeing messages`。

### 11.2 `logger`

```bash
logger -t 标签 -p err "消息内容"
logger -i -t app "带 PID 的日志"
logger -s -t app "同时输出到 stderr"
logger -f /path/file               # 把文件内容打成日志
```

| 参数 | 含义 |
|---|---|
| `-t` | 设置 `SYSLOG_IDENTIFIER` |
| `-p` | 设置优先级（`err`/`warning`/`info`/`debug`） |
| `-i` | 附上进程 PID |
| `-s` | 同时打到标准错误 |

**用途**：往日志里打标记（测试过滤、模拟故障、脚本里记关键节点）。**本次演练的三条日志就是它造的。**

### 11.3 `date` / `timedatectl`

```bash
date                              # 当前时间
date +%F\ %T                     # 2026-11-01 06:45:36
date +%s                          # Unix 时间戳
timedatectl                       # 时区、NTP 状态、本地/UTC 时间
sudo timedatectl set-timezone Asia/Shanghai
timedatectl list-timezones | grep -i shanghai
```

### 11.4 `wc` / `grep` 的组合用法

```bash
journalctl -b -1 -p err --no-pager | wc -l        # 数行数
journalctl -b -1 --no-pager | grep -i "Failed to start"
journalctl -b -1 -p warning --no-pager | grep -iE "fail|unable|denied"
journalctl -b -1 -p warning --no-pager | grep -vi lab05   # -v 反向排除
```

| 参数 | 含义 |
|---|---|
| `wc -l` | 数行数 |
| `grep -i` | 忽略大小写 |
| `grep -v` | 反向（排除匹配行） |
| `grep -E` | 扩展正则，支持 `\|` |
| `grep -c` | 只输出匹配行数 |

**`grep -v` 排除噪音是很实用的技巧**（比如把 `Firmware Bug` 过滤掉）。

### 11.5 `last` / `lastb` / `who`（登录审计）

```bash
last        # 读 /var/log/wtmp，成功登录记录
lastb       # 读 /var/log/btmp，失败登录记录（需 sudo）
who         # 当前在线用户
w           # 当前用户及其在干什么
```

**`lastb` 是查 SSH 爆破的第一现场**：如果看到成百上千条来自陌生 IP 的失败登录，说明被扫了。

### 11.6 `dmesg`

```bash
dmesg | tail -30
dmesg -T                  # 带人类可读时间戳
dmesg -l err,warn         # 按级别过滤
sudo dmesg -C             # 清空环形缓冲
```

**内核环形缓冲**，硬件问题（磁盘错误、网卡 reset、OOM killer）在这里找。**注意 `dmesg` 是独立缓冲，和 journal 不完全重合**。
